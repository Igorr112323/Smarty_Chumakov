# Мастер-промт для ИИ-агента: «сделай всё на GitHub»

> Этот текст отдаётся ИИ-агенту, у которого есть доступ к репозиторию на GitHub.
> Агент выполняет все шаги сам: пишет код, обучает и калибрует модель, прогоняет
> тесты, собирает `.exe` в GitHub Actions, публикует релиз. Человеку остаётся
> скачать готовый файл по одной ссылке и проверить его.
>
> Файл сохранён в репозитории как часть отчётности: работа по проекту
> выполнялась именно по этому заданию (см. `PROGRESS.md`, `ИТОГ.md`).

---

## 0. Роль и правила поведения

Ты — инженер-разработчик и исследователь. Ты работаешь **автономно**:

* **Не задавай вопросов.** Любую неопределённость решай сам и записывай
  решение с обоснованием в `PROGRESS.md` (что решил, почему, как проверил).
* **Пока не зелёное — не останавливайся.** Если проверка не проходит, ищи
  причину: исправляй код, признаки, обучение. Пока есть запасной путь —
  продолжай работу.
* **Коммить каждый законченный шаг** сообщением `шаг N: <что сделано>` и
  отправляй в текущую ветку.
* **Никаких выдуманных чисел.** Запрещено приводить несуществующие логи,
  метрики и выводы команд. Всё, что попадает в отчёт, должно быть получено
  запуском. Демо-числа отделяются от научных результатов и помечаются как
  демонстрация конвейера. Порог нельзя подгонять под тестовую выборку.

**Критерий готовности:** релиз с постоянной ссылкой на `.exe`, который запущен
и проверен в CI, зелёный набор тестов, отчёт без придуманных результатов,
журнал решений в `PROGRESS.md`.

## 1. Что делаем

Продукт: **проверка ответа по документу**. На вход — документ-контекст и ответ
(языковой модели или сотрудника). На выход — оценка недостоверности, найденные
спорные фрагменты, доли и метрики. Смысл: показать, какие места ответа
документ не подтверждает.

Ограничения окружения: только Windows-раннер GitHub Actions умеет собирать
`.exe`; ядро продукта пиши на стандартной библиотеке Python, чтобы бинарник
оставался компактным и запускался без установки.

2. **Код.** Реализуй структуру `src`-модуля `spanverify`:
   `core.py`, `features.py`, `aggregate.py`, `engine.py`, `train.py`,

   `scripts/exe_launcher.py`, `scripts/make_demo_dataset.py`,
   `scripts/make_markup_template.py`, `scripts/run_experiments.py`.
3. **Обучение и калибровка.** Обучение — на обучающей части, метрики — на
   отложенной. Запрещено подбирать порог по тесту.
4. **Тесты.** Не менее 60 тестов, покрытие не ниже 85 %, у каждого теста —
   содержательный docstring. Тесты-заглушки («проверим, что функция
   вызывается») запрещены.
5. **Пилот на реальной модели.** Небольшая русскоязычная модель
   (`ai-forever/rugpt3small_based_on_gpt2`, допустима

6. **Сборка `.exe`, смоук-тест, релиз.** Релиз публикуется только после
   успешного смоук-теста собранного файла.
7. **Русскоязычная документация.**
8. **Финальная самопроверка** по 10 пунктам, все — командами.
9. **Итоговое сообщение** пользователю: одна ссылка, что проверено, в чём
   ограничения.
10. **Таблица запасных путей** (см. п. 9) — на случай, если что-то недоступно.

## 3. Метод: как считается недостоверность

Три признака по каждому токену ответа (в режиме `hf` — из внимания модели,
в демо-режиме — лексические суррогаты):

1. `attention_entropy` — нормированная энтропия внимания последнего слоя;
2. `ctx_attention_mass` — масса внимания, пришедшая на токены контекста
   (**знак отрицательный**: чем больше опора на документ, тем ниже риск);
3. `embedding_density` — плотность близости к ближайшим фрагментам контекста.

Далее: `r = w1·Ĥ + w2·(1 − m̂) + w3·d̂` → сглаживание окном 3 → порог маски
`T = μ + z·σ` (устойчивая оценка к выбросам) → склейка соседних токенов →
расширение до границ предложения → метки (`likely_hallucination` при риске
≥ 0.75, иначе `doubtful`) → оценка ответа `s = 0.5·среднее + 0.5·среднее
верхних 20 %` → изотоническая калибровка (PAVA) → порог решения по целевому
FPR.

Веса признаков подбираются перебором сетки с суммой 1 по AUC на валидации;
дополнительно обучается голова (логистическая регрессия или MLP) с 5-кратной
кросс-валидацией, seed 42. Изотоническая калибровка — по целевому FPR 0.1.

Гипотеза, которую нужно проверить: **масса внимания на контекст информативнее
«сырой» энтропии внимания**. Если пилот её не подтвердит — так и напиши.

**Критерий качества:** token F1 ≥ 0.90 при FPR ≤ 0.10 на отложенных данных.
Не достигнут — улучшай признаки, а не порог.

## 4. Данные

Демонстрационный корпус: не менее 200 пар «контекст — ответ», три типа
(подтверждённый ответ, подмена значения, выдуманное утверждение). Внутри одного
документа шаблон не повторяется. Разметка — по символам ответа, чтобы метрики
считались и по токенам, и по фрагментам. Для разметки реальных документов
предусмотри `scripts/make_markup_template.py`.

## 5. Тесты, стиль, воспроизводимость

* не менее 60 тестов, docstring у каждого;
* покрытие ≥ 85 % (`--cov-fail-under=85`);
* `ruff` и `black` без замечаний;
* матрица: Python 3.10, 3.11, 3.12; ubuntu и windows;
* шаг воспроизводимости в CI: один seed → один результат (сверка хешей).

## 6. Пилот (реальная модель, CPU, CI)

* модель `ai-forever/rugpt3small_based_on_gpt2`;
* контрастные пары «с опорой на контекст» / «без опоры»; проверь контраст:
  доля ответов, воспроизводящих значение документа, ≥ 80 % в первой группе и
  ≤ 30 % во второй; не выдержано — напиши это в отчёте, а не подгоняй данные;
* AUC каждого признака с 95 % доверительным интервалом (бутстрэп, 5000
  итераций) **по слоям** `first`, `middle`, `-4`, `last`;
* сравнение с базовыми уровнями: случайное угадывание (0.5) и косинусная
  близость эмбеддингов без внимания;
* результат — артефакт CI (`pilot.md`, `pilot.json`), без придуманных чисел.

## 7. Сборка и релиз (Приложения А, Б, В)

**Приложение А. Workflow.** `windows-latest`, PyInstaller onefile,
`PYTHONUTF8=1`, запросы в UTF-8, порт **8765**, смоук-тест **до** публикации,
публикация релиза по тегу.

**Приложение Б. Смоук-тест.** Запустить собранный файл → `GET /health` отвечает
`ok` → `POST /v1/verify` с русским текстом → в JSON есть `score`, `spans`,
`ai_share`, `threshold` → минимум один фрагмент с меткой `doubtful` или
`likely_hallucination` → корректно остановить процесс. Плюс проверка, что
подтверждённый ответ получает вердикт `grounded`.

**Приложение В. Сборка.** onefile, `console=True`, `strip=True`, имя
`spanverify`, `datas` с `config`, `hiddenimports` (uvicorn/fastapi/starlette/
pydantic/anyio/h11/click и модули проекта — если выбран такой стек),
`excludes` (torch, transformers, faiss, streamlit, tkinter, unittest, pydoc,
pytest, setuptools, pip, matplotlib, pandas, scipy, PIL), точка входа
`scripts/exe_launcher.py` с флагами `--port` и `--no-browser`.

**Артефакты релиза:** `spanverify.exe` (onefile), `spanverify-win.zip` (onedir),
`spanverify.pyz` (zipapp) и `SHA256SUMS.txt`. Калибратор и веса — внутри
бандла, чтобы файл работал сам по себе. Постоянная ссылка:

```
https://github.com/<owner>/<repo>/releases/latest/download/spanverify.exe
```

## 8. Контракт API (Приложение Г)

`POST /v1/verify`

```json
{
  "answer": "текст ответа",
  "context": "документ-источник",
  "prompt": "необязательно",
  "max_new_tokens": 256,
  "with_tokens": false
}
```

Ответ:

```json
{
  "score": 0.0,
  "is_hallucination": false,
  "ai_share": 0.0,
  "ai_share_hard": 0.0,
  "threshold": 0.5,
  "spans": [{"start": 0, "end": 0, "text": "", "risk": 0.0, "label": "doubtful"}],
  "latency_ms": 0.0,
  "mode": "demo",
  "stats": {
    "token_count": 0, "mean_risk": 0.0, "p90_risk": 0.0,
    "raw_score": 0.0, "span_threshold": 0.0, "warning": ""
  }
}
```

Справочные маршруты: `GET /` (интерфейс), `GET /health`, `GET /v1/config`,
`GET /v1/model`.

`config/weights.json`:

```json
{

```

## 9. Запасные пути (если что-то недоступно)

| Препятствие | Запасной путь | Как сообщить |
| --- | --- | --- |
| Нет прав на запись в репозиторий | работай в своей ветке и приложи патч | «изменения в ветке, нужен merge» |
| Нет доступа к huggingface.co | собери пакет с моделью заранее либо пометь пилот как невыполненный | «пилот не выполнен: нет доступа к весам» |
| Нельзя собрать `.exe` локально | собирай в GitHub Actions на `windows-latest` | «.exe собран и проверен в CI» |
| Тесты не проходят | исправляй код, при необходимости упрощай признаки | «что именно падало и что изменено» |
| Покрытие ниже 85 % | добавляй содержательные тесты, не заглушки | «покрытие N %, добавлены тесты на …» |
| Не хватает данных для обучения | используй синтетику и честно помечай результат | «это демонстрация конвейера, не научный вывод» |
| Релиз не публикуется | проверь права токена и тег; приложи артефакты | «артефакты во вложениях сборки» |

1. Одна постоянная ссылка на `.exe`.
