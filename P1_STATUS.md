### Задача 2.2: Унификация вычислительного пути ⚠️ ТРЕБУЕТ РАБОТЫ

**Проблема:** В oof.py используется упрощённая логика сглаживания, которая отличается от публичного Verifier:
- В oof.py: создаётся risk_sequence длиной max_index+1, сглаживается, извлекаются scored токены
- В engine.py verify(): создаётся полная последовательность masked с нулями для не-scored токенов, сглаживается вся последовательность, извлекаются scored значения

**Анализ:**
Прочитан код verify() в engine.py (строки 395-495). Ключевые отличия:
1. verify() создаёт полную последовательность risk для всех токенов
2. Создаёт masked последовательность с нулями для не-scored токенов
3. Применяет _smooth() ко всей masked последовательности
4. Извлекает scored значения для scored_indices

В oof.py:
1. Есть только samples (scored токены), нет всех токенов
2. Создаётся risk_sequence длиной max_index+1 (не полная длина)
3. Сглаживается только risk_sequence
4. Извлекаются scored токены

**Требуемая работа:**
1. Создать функцию `compute_answer_score_from_samples()` в oof.py, которая:
   - Получает все токены из pair["answer"]
   - Создаёт полную последовательность risk
   - Обнуляет риск для не-scored токенов
   - Применяет _smooth() к полной последовательности
   - Извлекает scored значения
   - Вычисляет answer_score

2. Заменить текущую логику сглаживания в oof.py на использование этой функции

3. Создать тесты для проверки совпадения результатов между oof.py и публичным Verifier

**Статус:** Анализ выполнен, план создан, код не изменён
