# Техническое задание и календарный план научно-исследовательской работы

**Тема:** метод и программное средство проверки достоверности текста по
документу-источнику на основе анализа внимания языковой модели (SpanVerify).

Формулировки видов работ — научно-исследовательские. Виды работ, не относящиеся
к НИР (производство, изготовление образцов, сертификация, упаковка, маркетинг,
продвижение, конструкторская и технологическая документация, закупка
оборудования, клинические испытания, патентование, публикация статьи и участие
в конференции как результат, преакселерация, бизнес-план), в план не включены.

---

## 1. Техническое задание

### 1.1. Основание и цель

Основание: практическая потребность в выборочной проверке текстов, которые
готовятся по документам (справки, ответы на запросы, обобщения регламентов).

Цель работы: разработать и исследовать метод, который по документу-источнику и
ответу указывает фрагменты ответа, не подтверждённые документом, и даёт
количественную оценку достоверности ответа; реализовать метод в виде
программного средства, пригодного к использованию на обычном рабочем
компьютере.

### 1.2. Задачи работы

1. Исследовать существующие подходы к проверке соответствия текста источнику и
   определить постановку задачи для русскоязычных текстов.
2. Разработать признаки недостоверности на основе внимания языковой модели и
   векторных представлений; изучить знак и информативность каждого признака.
3. Разработать схему агрегации: агрегация признаков по токенам, выделение
   связных фрагментов, расширение до границ предложения, оценка ответа в целом.
4. Разработать процедуру обучения и калибровки по целевому уровню ложных
   срабатываний, исключающую подбор порога по тестовой выборке.
5. Провести вычислительные эксперименты: метрики по токенам и фрагментам,
   сравнение признаков между собой и по слоям модели, доверительные интервалы.
6. Разработать программное средство: локальное приложение, HTTP-интерфейс,
   интерфейс командной строки; обеспечить воспроизводимость сборки.
7. Подготовить отчётность: описание метода, руководство пользователя, отчёт о
   НИР, документацию по обучению на собственных данных.

### 1.3. Объект и предмет исследования

Объект — пары «документ-источник — ответ» (ответы языковых моделей и людей).
Предмет — связь между опорой фрагментов ответа на документ и внутренними
сигналами языковой модели; методы локализации неподтверждённых фрагментов.

### 1.4. Методы исследования

* анализ подходов к проверке фактической опоры текста на источник;
* вычислительный эксперимент на размеченных парах;
* статистическая оценка: precision, recall, F1, FPR, AUC, доверительные
  интервалы методом бутстрэпа, парные сравнения;
* сравнение признаков и слоёв модели;
* воспроизводимые автоматические проверки (непрерывная интеграция).

### 1.5. Требования к результатам

| № | Требование | Форма представления |
| --- | --- | --- |
| 1 | Описание метода: признаки, агрегация, пороги, калибровка | разделы отчёта о НИР и `README` модуля |
| 2 | Параметры метода, воспроизводимые по seed | `config/weights.json`, `config/head.json` |
| 3 | Программное средство | `.exe` для Windows (один файл), `.pyz`, HTTP-интерфейс, CLI |
| 4 | Оценка качества на отложенной части | отчёт прогона, файл метрик |
| 5 | Пилотное исследование по слоям реальной модели | отчёт пилота (артефакт запуска) |
| 6 | Руководство пользователя | `docs/РУКОВОДСТВО.md` |
| 7 | Отчёт о НИР | `docs/ОТЧЁТ_о_НИР_шаблон.md` + материалы репозитория |

### 1.6. Критерии приёмки

| Критерий | Значение | Способ проверки |
| --- | --- | --- |
| Качество по токенам на отложенной части | F1 ≥ 0.90 | `python -m spanverify evaluate --dataset data/demo_pairs.jsonl` |
| Ложные срабатывания | FPR ≤ 0.10 | там же |
| Воспроизводимость обучения | одинаковый seed → одинаковый файл параметров | сверка контрольной суммы в CI |
| Автоматические проверки | все проходят | GitHub Actions: тесты, покрытие ≥ 85 %, стиль |
| Работоспособность приложения | запускается и отвечает | смоук-тест собранного `.exe` в CI |
| Отсутствие подбора порога по тесту | подтверждается кодом и журналом | `train.py`, `PROGRESS.md` |

### 1.7. Ограничения и допущения

* Вычисления — на CPU; модель признаков небольшая (зависимость от выбора модели
  указана в отчёте).
* Демонстрационный корпус синтетический; для прикладных выводов требуется
  разметка пользователя.
* Пилот ограничен объёмом в десятки контрастных пар; доверительные интервалы
  широкие.

## 2. Календарный план

Сроки указаны в месяцах от начала работы; календарные даты проставляются при
подаче заявки.

| Этап | Содержание работы | Результат этапа | Срок |
| --- | --- | --- | --- |
| 1 | Исследование подходов, постановка задачи, выбор признаков | аналитическая записка, постановка задачи | 1-й месяц |
| 2 | Реализация признаков и схемы агрегации; подготовка размеченного набора пар | описание признаков, размеченный набор | 2–3-й месяцы |
| 3 | Обучение и калибровка метода по целевому уровню ложных срабатываний | обученные параметры, воспроизводимая процедура обучения | 4-й месяц |
| 4 | Оценка качества на отложенной части; метрики по токенам и фрагментам | протокол эксперимента, таблицы метрик | 5-й месяц |
| 5 | Пилотное исследование признаков по слоям реальной модели | отчёт пилота с доверительными интервалами | 6-й месяц |
| 6 | Разработка программного средства (приложение, HTTP-интерфейс, CLI) | работающее средство | 7–8-й месяцы |
| 7 | Апробация на контрольных примерах, автоматические проверки, документация | руководство пользователя, протоколы проверок | 9-й месяц |
| 8 | Обобщение результатов, отчёт о НИР | отчёт о НИР | 10-й месяц |

### 2.1. Результаты по этапам (формулировки для заявки)

* Этапы 1–2: постановка задачи; описание признаков и агрегации; размеченный
  набор пар с разметкой по символам.
* Этапы 3–5: обученные параметры; метрики качества; результаты сравнения
  признаков и слоёв модели; выводы об информативности сигналов.
* Этапы 6–7: программное средство и документация; протоколы автоматических
  проверок.
* Этап 8: отчёт о НИР с разделением демонстрационных и научных результатов.

### 2.2. Риски и способы их снижения

| Риск | Снижение |
| --- | --- |
| Слабая информативность признаков на реальных текстах | парные эксперименты, расширение набора признаков, калибровка на данных пользователя |
| Ограниченные вычислительные ресурсы | вычисления на CPU, малая модель, разбиение анализа по слоям |
| Недоступность весов модели | локальный кэш весов; замена на другую открытую модель |
| Недостаток размеченных данных | приоритет малых, но аккуратно размеченных наборов; шаблон разметки в комплекте |

### 2.3. Формы отчётности

1. Промежуточный отчёт по этапам 1–3 (метод, параметры, процедура обучения).
2. Отчёт по экспериментальной части (метрики, сравнение признаков, пилот).
3. Итоговый отчёт о НИР с приложениями: руководство пользователя, описание
   воспроизведения экспериментов, журнал работы.

документация подготовлена (`docs/РУКОВОДСТВО.md`, `PROGRESS.md`, `ИТОГ.md`).
