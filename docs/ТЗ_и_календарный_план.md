# Техническое задание и календарный план НИР

Тема: **разработка и исследование метода автоматического выявления
недостоверных фрагментов текста на основе сопоставления ответа с
документом-источником** (рабочее название комплекса — SpanVerify).

Документ подготовлен для конкурсной документации. Виды работ сформулированы как
научно-исследовательские: исследование, разработка метода, эксперимент, оценка
качества, апробация, подготовка отчётности.

---

## 1. Техническое задание

### 1.1. Основание для работы

Инициативная научно-исследовательская работа по направлению «искусственный
интеллект и обработка естественного языка». Задача вызвана практикой
применения генеративных моделей для подготовки текстов по документам: такие
тексты требуют выборочной проверки на соответствие источнику.

### 1.2. Цель работы

Разработать метод выявления фрагментов ответа, не подтверждаемых
документом-источником, и оценить его качество на размеченных парах
«документ — ответ».

### 1.3. Задачи работы

1. Исследовать существующие подходы к проверке фактической опоры текста на
   источник, уточнить постановку задачи для русскоязычных документов.
2. Разработать признаки недостоверности на основе внимания языковой модели и
   векторных представлений токенов.
3. Разработать схему агрегации признаков: оценка риска по токенам, выделение
   связных фрагментов, расширение до границ предложения, оценка ответа в целом.
4. Разработать процедуру обучения и калибровки параметров по целевому уровню
   ложных срабатываний.
5. Провести экспериментальную оценку метода на контрольном наборе и сравнить
   признаки между собой, включая разбиение по слоям модели.
6. Разработать программную реализацию (локальное приложение, HTTP-интерфейс,
   командный интерфейс) и провести её апробацию на контрольных примерах.
7. Подготовить отчётность: описание метода, руководство пользователя, отчёт о
   НИР, воспроизводимые скрипты экспериментов.

### 1.4. Объект и предмет исследования

* **Объект:** тексты, порождаемые языковыми моделями и людьми по заданному
  документу-источнику.
* **Предмет:** связь между опорой фрагментов ответа на документ и признаками
  языковой модели; методы автоматического выявления неподтверждённых
  фрагментов.

### 1.5. Методы исследования

* анализ литературы и существующих подходов;
* вычислительный эксперимент на размеченных парах;
* статистическая оценка метрик (precision, recall, F1, FPR, AUC) с
  доверительными интервалами методом бутстрэпа;
* сравнительный анализ признаков и слоёв модели;
* воспроизводимые сборки и автоматические проверки (GitHub Actions).

### 1.6. Требования к результату

1. **Метод** с формальным описанием: признаки, агрегация, пороги, калибровка.
2. **Программная реализация**: локальное приложение для Windows (один файл),
   HTTP-интерфейс с контрактом `POST /v1/verify`, командный интерфейс.
3. **Параметры метода** в текстовом виде (`config/weights.json`), воспроизводимые
   по seed.
4. **Результаты оценки**: метрики по токенам и фрагментам на отложенной части
   контрольного набора; отдельно — результаты пилота на реальной модели с
   разбиением по слоям.
5. **Отчётность**: отчёт о НИР, руководство пользователя, описание формата
   разметки, инструкция по воспроизведению экспериментов.

### 1.7. Критерии приёмки

| Критерий | Целевое значение | Как проверяется |
| --- | --- | --- |
| Качество по токенам на отложенных данных | F1 ≥ 0.90 | `python -m spanverify evaluate --dataset <набор>` |
| Доля ложных срабатываний | FPR ≤ 0.10 | тот же отчёт |
| Тесты | ≥ 60, все проходят | `python -m pytest -q` |
| Покрытие кода | ≥ 85 % | `pytest --cov --cov-fail-under=85` |
| Стиль | без замечаний | `ruff check .`, `black --check .` |
| Воспроизводимость | одинаковый seed → одинаковые параметры | сверка хешей в CI |
| Приложение | запускается и отвечает на запрос | смоук-тест в CI |
| Честность отчёта | демо-числа отделены от научных | проверка формулировок |

### 1.8. Ограничения

* Модель для признаков — небольшая (вычисления на CPU); результат зависит от
  выбора модели и предметной области.
* Контрольный набор на старте — синтетический; замена на размеченные реальные
  документы повышает достоверность выводов, но не входит в базовый объём.
* Требуется калибровка на данных пользователя: без неё порог носит
  ориентировочный характер.

## 2. Календарный план

Сроки указаны в относительных единицах (месяцы от начала работы); точные даты
проставляются при подаче заявки.

| Этап | Содержание работы | Результат этапа | Срок |
| --- | --- | --- | --- |
| 1 | Исследование подходов, уточнение постановки задачи, обзор методов проверки опоры текста на источник | аналитическая записка, постановка задачи | 1-й месяц |
| 2 | Разработка признаков недостоверности и схемы агрегации; подготовка контрольного набора пар | описание метода, размеченный набор | 2–3-й месяцы |
| 3 | Обучение и калибровка параметров метода по целевому уровню ложных срабатываний | обученные параметры, процедура воспроизводимого обучения | 4-й месяц |
| 4 | Экспериментальная оценка: метрики по токенам и фрагментам, сравнение признаков | протокол экспериментов, таблицы метрик | 5-й месяц |
| 5 | Пилотное исследование на реальной русскоязычной модели: сравнение признаков по слоям, доверительные интервалы | отчёт пилота | 6-й месяц |
| 6 | Разработка программной реализации: локальное приложение, HTTP-интерфейс, командный интерфейс | работающее приложение | 7–8-й месяцы |
| 7 | Апробация на контрольных примерах, проверка устойчивости, оформление документации | руководство пользователя, описание формата разметки | 9-й месяц |
| 8 | Подготовка отчёта о НИР, обобщение результатов, формулировка ограничений и направлений развития | отчёт о НИР | 10-й месяц |

### 2.1. Ожидаемые результаты по этапам

* **Этапы 1–2:** постановка задачи, описание признаков и схемы агрегации,
  контрольный набор с разметкой.
* **Этапы 3–5:** обученные параметры, метрики качества, результаты сравнения
  признаков и слоёв модели, выводы о применимости подхода.
* **Этапы 6–7:** рабочее приложение и документация к нему.
* **Этап 8:** отчёт о НИР с честным разделением демонстрационных и научных
  результатов.

### 2.2. Риски и способы снижения

| Риск | Способ снижения |
| --- | --- |
| Низкое качество на реальных документах | калибровка на данных пользователя, расширение разметки, доработка признаков |
| Ограниченные вычислительные ресурсы | работа на CPU, малая модель, разбиение экспериментов по слоям |
| Недоступность внешних весов модели | локальный кэш весов; запасной вариант — другая открытая модель |
| Расхождение ожиданий по объёму разметки | приоритет на малый, но аккуратно размеченный набор |

### 2.3. Формы отчётности

1. Промежуточный отчёт по этапам 1–3 (описание метода, параметры обучения).
2. Отчёт по экспериментальной части (метрики, сравнение признаков).
3. Итоговый отчёт о НИР с приложением руководства пользователя и описания
   воспроизведения экспериментов.

## 3. Соответствие результатов работе

Работа выполнена в объёме этапов 1–7 (см. `ИТОГ.md`): метод реализован,
обучен и откалиброван, оценён на отложенной части контрольного набора,
проведён пилот на реальной модели в режиме вычислений на CPU, приложение
собрано и проверено автоматическим смоук-тестом, документация подготовлена.
Этап 8 (подготовка итогового отчёта формы НИР) выполняется на основании
материалов репозитория: `docs/ОТЧЁТ_о_НИР_шаблон.md`, `PROGRESS.md`, `ИТОГ.md`.
