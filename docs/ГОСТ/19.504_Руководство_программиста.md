## 1. Область применения

Документ описывает внутреннее устройство программы: состав модулей, точки
расширения, порядок добавления признаков и режимов, требования к тестам.

## 2. Структура пакета

```
spanverify/
  core.py         типы, токенизация со смещениями, границы предложений и клауз
  features.py     признаки demo и hf, привязка числа к объекту
  engine.py       конвейер: признаки → риск → фрагменты → калибровка → вердикт
  normalize.py    числа прописью, единицы, даты, стеммер
  coverage.py     покрытие фактов документа ответом (отключено по умолчанию)
  calibration.py  изотоническая калибровка
  train.py        обучение весов, логистической головы, калибровки
  participation.py  оценка доли участия ИИ
  detector.py     историческая ветка: детектор «написано ли ИИ» без контекста
  cli.py          командная строка
  server.py       HTTP API
  webui.py        встроенный веб-интерфейс (без зависимостей)
  backends/hf.py  бэкенд на transformers
```

## 3. Точки расширения

### 3.1. Добавление признака

Признак — число для каждого токена ответа. Добавляется в
`spanverify/features.py::demo_features` (суррогат) или `hf_features` (модель).
Свёртка признаков в риск — `combine(...)` с весами из `config/weights.json`
(порядок весов: `attention_entropy`, `ctx_attention_mass`, `embedding_density`).

Требование: новый признак обязан быть покрыт тестом и измерен числом (AUC или
прирост F1 на отложенной части). Изменение без числа не принимается.

### 3.2. Добавление режима

Режим задаётся параметром `mode` (`demo` или `hf`) и выбирает реализацию в
`extract_features`. **Тихая подмена режима запрещена**: если запрошен `hf`, а
зависимости недоступны, выбрасывается `BackendUnavailable` с указанием
`requirements-hf.txt`; командная строка возвращает код 2. Проверяется тестом
`tests/test_hf_no_silent_fallback.py`.

### 3.3. Покрытие фактов

`spanverify/coverage.py` реализует сверку фактов документа с ответом:
`mentioned` / `distorted` / `omitted` / `partial` / `irrelevant`. Механизм
выключен по умолчанию (`Verifier(coverage=False)`) по результатам измерения
(см. раздел 6 «Описания программы»). Включается явно для доработки.

## 4. Ключевые инварианты

1. **Непрерывное покрытие токенов.** Склейка токенов через пробел обязана
   восстанавливать исходный текст: от этого зависят смещения фрагментов.
2. **Порог не подбирается по тестовой части.** Калибровка — на обучающей
   (или валидационной), измерение — на отложенной, разбиение — по документам.
3. **Числа не теряются при нормализации.** `normalize_for_match` сохраняет
   цифры: иначе «10 лет» и «3 года» стали бы одинаковыми.
4. **Число прописью — одно число.** Значение считается для группы токенов
   (`_group_number_values`), а не по отдельному токену.
5. **Границы фрагмента не обрезают найденные токены** (`_shrink_to_clause`).

## 5. Тесты

```bash
cd spanverify-module
python -m pytest -q                                            # 397 тестов
python -m pytest --cov=spanverify --cov-report=term-missing --cov-fail-under=85
python -m ruff check .
python -m black --check .
python scripts/check_numbers.py
```

Тесты-заглушки запрещены. Каждый тест содержит docstring со смыслом проверки.
Новые пути обязаны поднимать, а не снижать покрытие (порог 85 % в CI).

## 6. Воспроизводимость

Один seed → один результат. CI сверяет SHA256 трёх артефактов обучения:
`weights.json`, `head.json`, `participation.json`.

```bash
python -m spanverify train --dataset data/demo_pairs.jsonl --out /tmp/w.json --seed 42 --folds 5
```

## 7. Формат корпуса

Файл JSONL, по одной паре на строку. Обязательные поля: `context`, `answer`.
Необязательные: `id`, `labels`, `meta`. `labels` — список `[start, end, тип]`
по символам ответа. Чужой формат отвергается с кодом 2 и указанием строки.

Обучение и калибровка на внешних наборах (RAGTruth, RusHallu-RAG) **запрещены**:
они используются только как тест. Сырые данные внешних бенчмарков в репозиторий
не попадают (`data/external/` в `.gitignore`).
