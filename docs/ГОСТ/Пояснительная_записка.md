# Пояснительная записка

**Обозначение документа:** `Smarty_Chumakov.00002-01 81 01-1`
**ГОСТ 19.404-79** (структура пояснительной записки)
**Программа:** SpanVerify, версия 1.3.0 · коммит `39453a6`

---

## 1. Основание для разработки

Разработка выполнена в рамках НИР по заявке в АС «Фонд-М» (У-640148). Задача —
создать программу, которая по документу-источнику и ответу указывает фрагменты
ответа, не подтверждённые документом, и оценивает долю участия ИИ.

## 2. Назначение разработки

Практическая задача: сотрудник получает ответ (от языковой модели или коллеги)
по регламенту и должен понять, можно ли на него опираться. Проверка вручную
долгая и Subjective; программа делает её воспроизводимой и даёт указание на
конкретное место в тексте.

## 3. Выбор технических решений

| Решение | Обоснование |
|---|---|
| Ядро на стандартной библиотеке Python | программа обязана работать без установки и без сети; `.exe` не тянет `torch` |
| Токенизация с непрерывным покрытием | смещения фрагментов должны быть точными: без этого невозможна локализация |
| Два режима (`demo` и `hf`) | разделить проверку конвейера и научный результат; запретить выдачу demo за hf |
| Сужение фрагмента до клаузы | расширение до предложения давало ширину ×24 и span-F1 0,098 — это не локализация |
| Группировка числовых токенов | «двадцать пять» — одно число; по одному токену корректный ответ получал ложное замечание |
| Изотоническая калибровка и порог на обучающей части | требование: порог не подбирается по тесту |
| Внешние наборы только как тест | обучение на них запрещено: иначе метрики перестают быть внешней проверкой |

## 4. Описание разработки

Разработка шла итерациями с обязательным измерением: каждое изменение признаков
или конвейера сопровождалось прогоном на отложенной части и записью чисел в
`reports/METRICS.json`. Решения, не прошедшие измерение, в продукт не включались
— так отключён механизм покрытия фактов.

## 6. Выводы

Программа работоспособна и решает задачу локализации расхождений в режиме
`demo` на синтетических корпусах. Главные незакрытые вопросы — режим `hf`,
корпус на реальных актах и устойчивость к перефразированию. Они носят
содержательный, а не «косметический» характер, и требуют вычислительных
ресурсов и доступа к источникам, которых в среде разработки нет.
