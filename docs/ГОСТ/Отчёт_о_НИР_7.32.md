# Отчёт о научно-исследовательской работе

**ГОСТ 7.32-2017** «Отчёт о НИР. Структура и правила оформления»
**Тема:** Разработка метода и программы проверки ответа на соответствие документу-источнику с оценкой доли участия ИИ (SpanVerify)
**Версия программы:** 1.3.0 · **коммит:** `39453a6`

Правило отчёта: каждое число — вывод выполненной команды. Источник чисел —
`spanverify-module/reports/METRICS.json`. Не измеренное помечено `null` с причиной.

---

## Реферат

**Объект исследования** — ответ (языковой модели или сотрудника), содержащий
утверждения о документе-источнике.

**Цель работы** — создать метод и программу, которые указывают фрагменты ответа,
не подтверждённые документом, и оценивают долю участия ИИ в тексте.

**Метод** — сверка токенов ответа с измерениями документа: признаки лексической
поддержки, привязка числа к объекту документа, сужение границ фрагмента до
клаузы, калибровка вероятности и порог решения на обучающей части.

**Результаты.** На отложенной части корпуса A (1200 пар, разбиение по документам
840/180/180, режим `demo`): token F1 0,688 при FPR 0,001; строгий span-F1 0,717
при ширине фрагмента ×1,1; ложных замечаний на чистых парах 0,0 %.
На демонстрационном корпусе (240 пар): token F1 0,953 при FPR 0,002.

**Отрицательные результаты.** Режим реальной языковой модели не прогнан
ни разу (`hf_runs = 0`): нет GPU, доступ к весам закрыт. Пилот на малой модели
ранее дал AUC 0,405–0,700 при типичном ~0,50. Пропуск существенного сведения
не обнаруживается (recall 0,000). Корпус на реальных актах не собран (10
документов из 120).

**Вывод.** Метод работоспособен на синтетических данных и даёт точную
локализацию расхождений, но его применимость к реальным документам
экспериментально не подтверждена.

## 1. Введение

Ответы языковых моделей и тексты сотрудников содержат утверждения о документах
(регламентах, нормативных актах). Проверка таких утверждений вручную дорога и
невоспроизводима. Задача программы — сделать проверку автоматической и
указывать конкретное место в тексте, где документ не подтверждает ответ.

## 2. Постановка задачи

Даны документ-источник `D` и ответ `A`. Требуется:

* найти фрагменты `A`, которые `D` не подтверждает;
* оценить риск по ответу в целом;
* оценить долю участия ИИ в тексте ответа.

Ограничения: работа локально, без сети; порог решения не подбирается по
тестовой части; разбиение корпуса — по документам.

## 3. Метод и алгоритм

1. Токенизация ответа с сохранением символьных смещений (непрерывное покрытие).
2. Признаки токена:
   * режим `demo` — лексические суррогаты: поддержка контекстом, близость
     триграмм, шаблонность, привязка числа к объекту;
   * режим `hf` — энтропия внимания, масса внимания на контекст, плотность
     скрытых состояний (реализовано, но не прогонялось).
3. Свёртка признаков в риск; сглаживание; порог маски.
4. Границы фрагмента: склейка соседних токенов и сужение до клаузы.
5. Правило привязки числа к объекту поверх маски (текстовое, поверх модели).
6. Калибровка оценки ответа (изотоническая); вердикт по порогу.

Нормализация: числа прописью → цифры, единицы → каноническая форма, даты →
`ДД.ММ.ГГГГ`, грубый стеммер. Число прописью обрабатывается как одно число
(группа токенов), а не как отдельные токены.

## 4. Экспериментальная часть

**Корпусы.**

| Корпус | Состав | Статус |
|---|---|---|
| Демонстрационный | 240 пар, синтетика, групповой сплит | собран |
| Корпус A (A1) | 1200 пар, синтетические документы, 8 типов расхождений, сплиты 840/180/180, `shared_groups: 0` | собран |
| Корпус A2 | ответы реальной модели по реальным документам | только `--dry-run`, числа не измерены |
| Корпус A3 | реальные опубликованные акты | **не собран**: 10 документов из 120, `manifest.json` нет |
| Корпус B | RusHallu-RAG (1000 пар, человеческая разметка) | подключён как тест |

**Команды.**

```bash
cd spanverify-module
python -m spanverify evaluate --dataset data/corpus_a/pairs.jsonl
python scripts/collect_metrics.py --seed 42 --out reports/METRICS.json
python scripts/cross_corpus.py --out reports/cross_corpus.json
python -m pytest -q
```

**Аппаратура.** CPU 2 ядра, 3,9 ГБ ОЗУ, GPU отсутствует, ОС Linux, Python 3.11.2.

## 5. Результаты

### 5.1. Качество на корпусе A (режим `demo`)

| Показатель | Отложенная часть |
|---|---|
| Token precision / recall / F1 | 1,000 / 0,529 / 0,688 |
| Token FPR / AUC | 0,001 / 0,935 |
| Строгий span-F1 (IoU ≥ 0,5) | 0,717 |
| Полнота по покрытию | 0,573 |
| Ширина фрагмента | ×1,1 |
| Вердикт precision / recall / F1 | 0,992 / 0,388 / 0,558 |

### 5.2. Ложные замечания на чистых парах

| Состояние | Доля |
|---|---|
| До исправления привязки числа | 0,136 |
| После | **0,000** |

Причина ложных замечаний: правило привязки числа брало значение по одному
токену, из-за чего «двадцать пять» превращалось в «20» и «5», не совпадало с
«25» в документе и обвинялось в заимствовании у чужого объекта.

### 5.3. Устойчивость

| Проверка | Результат |
|---|---|
| Перенос на другой генератор (числа словами, другие шаблоны) | token F1 0,953 → 0,717, FPR 0,157 |
| Внешний набор RAGTruth (QA, режим demo) | token F1 0,204, FPR 0,169 |
| Внешний набор RusHallu-RAG (режим demo) | token F1 0,127; их метрики: accuracy 0,424, ROUGE-L 0,533 |
| Пять видов искажений (перефразирование, подмена, противоречие, пропуск, числа прописью) | **не измерено** (`null`): отчёт `reports/robustness.md` не создан |

### 5.4. Режим `hf`

Прогонов: **0**. Причина: GPU отсутствует, доступ к весам моделей
(`huggingface.co`) из среды выполнения закрыт. Реализована защита от подмены:
запрос режима `hf` без зависимостей даёт явную ошибку с кодом 2, а не тихий
переход на `demo`.

Пилот на малой модели `ruGPT3-small` (ранее, CPU, 48 пар, бутстрэп 5000):
AUC признаков по слоям 0,405–0,700, типично ~0,50 — признаки внимания не
различают подставленное число и правильное.

### 5.5. Функциональные испытания

**Не проводились.** Размеры файлов поставки, время обработки текстов 500 /
2 000 / 10 000 / 50 000 символов, пиковая память, максимальная длина текста,
утечка памяти — всё `null`.

### 5.6. Аналоги

Baseline-числа из статей (RAGTruth, RusHallu-RAG, SelfCheckGPT): **не извлечены**
(`null`). Причина: PDF статей недоступен (`scripts/extract_baseline_pdf.py`).

## 6. Обсуждение и ограничения

* Метод опирается на лексическое совпадение; на свободных пересказах качество
  падает до 0,10–0,20.
* Пропуск сведения не обнаруживается: механизм покрытия фактов написан, но
  отключён — он давал больше ложных замечаний, чем находок.
* Режим `hf` не измерен, поэтому научный вывод о применимости сделать нельзя.
* Оценка доли участия ИИ калибрована на синтетике:
  `synthetic-participation-corpus 1.0`.
* Ручная валидация разметки: проверенных человеком пар — 0.

## 7. Заключение

1. Конвейер проверки ответа по документу работоспособен и воспроизводим:
   397 тестов, CI зелёный на трёх версиях Python и двух ОС.
2. Локализация расхождений вышла на точность, пригодную для практики:
   строгий span-F1 0,717 при ширине фрагмента ×1,1 (было 0,098 при ×24).
3. Ложные замечания на корректных ответах устранены полностью (0,000).
4. Главное ограничение — режим реальной языковой модели не прогнан ни разу,
   корпус на реальных актах не собран, устойчивость к перефразированию
   не обеспечена. До закрытия этих пунктов выводы о применимости на реальных
   документах делать нельзя.
