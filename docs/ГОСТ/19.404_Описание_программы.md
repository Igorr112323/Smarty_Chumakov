## 1. Общие сведения

Программа SpanVerify предназначена для проверки ответа (языковой модели или
сотрудника) на соответствие документу-источнику: программа указывает фрагменты
ответа, которые документ не подтверждает, и оценивает долю участия ИИ в тексте.

Работает локально, без обращения к внешним сервисам. Реализована на языке
Python 3.10+; ядро, командная строка, HTTP-интерфейс и веб-интерфейс работают на
стандартной библиотеке без сторонних зависимостей.

| Свойство | Значение |
|---|---|
| Язык реализации | Python 3.10 / 3.11 / 3.12 |
| Зависимости ядра | отсутствуют (стандартная библиотека) |
| Зависимости режима `hf` | `torch~=2.14`, `transformers~=5.18`, `sentencepiece~=0.2` |
| Интерфейсы | командная строка, HTTP API, встроенный веб-интерфейс |
| Автоматические тесты | 397 (прогон: `python -m pytest -q`) |
| Статус CI | тесты на Python 3.10–3.12, ubuntu и windows — зелёные (прогон от коммита `39453a6`) |

## 2. Функциональное назначение

Программа решает одну задачу: по паре «документ-источник — ответ» найти места
ответа, которые документ не подтверждает, и выдать оценку риска.

Функции:

1. **Токенизация с непрерывным покрытием.** Объединение токенов через пробел
   восстанавливает исходный текст, поэтому смещения фрагментов точны.
2. **Расчёт признаков** в двух режимах: `demo` (лексические суррогаты) и `hf`
   (внимание и скрытые состояния реальной языковой модели).
3. **Локализация спорных фрагментов** с точными границами (сужение до клаузы).
4. **Правило привязки числа к объекту** (дефект D): число ответа сверяется с
   измерениями того же объекта документа.
5. **Проверка покрытия фактов документа ответом** (типы `missing` и `partial`) —
   механизм implemented, но **в продукте отключён** (причина и замер — раздел 6).
6. **Оценка доли участия ИИ** (`ai_participation`).
7. **Вердикт** по ответу: `grounded` / `doubtful` / `likely_hallucination`.

## 4. Входные и выходные данные

**Вход:** `answer` — проверяемый текст; `context` — документ-источник (строка
или список фрагментов); необязательные `prompt`, `max_new_tokens` (режим `hf`).

**Выход** (`POST /v1/verify`): `score`, `verdict`, `is_hallucination`,
`ai_share`, `ai_share_hard`, `ai_participation`, `threshold`, `spans`
(`start`, `end`, `text`, `risk`, `label`), `latency_ms`, `mode`, `stats`.

**Коды возврата команды `verify`:** `0` — ответ подтверждён, `1` — найдены
спорные фрагменты, `2` — ошибка вызова (включая запрос режима `hf` без
установленных зависимостей).

## 5. Описание алгоритма

1. Токенизация ответа с сохранением символьных смещений.
2. Расчёт признаков: лексические суррогаты (`demo`) либо внимание и скрытые
   состояния модели (`hf`).
3. Свёртка признаков в риск токена; сглаживание; порог маски.
4. Формирование фрагментов: склейка соседних токенов и **сужение до клаузы**,
   в которой стоит спорное значение.
5. Правило привязки числа к объекту поверх маски.
6. Калибровка оценки ответа; вердикт по порогу, выбранному на обучающей части.

Порог решения **не подбирается по тестовой части**: обучение и калибровка идут
на обучающей, измерение — на отложенной, разбиение — по документам
(`shared_groups: 0`).

## 6. Технические характеристики (измерено)

Режим `demo`, корпус A (1200 пар, разбиение по документам 840/180/180):

| Показатель | Отложенная часть | Команда |
|---|---|---|
| Token precision / recall / F1 | 1,000 / 0,529 / **0,688** | `python -m spanverify evaluate --dataset data/corpus_a/pairs.jsonl` |
| Token FPR | **0,001** | то же |
| Token AUC | 0,935 | то же |
| Строгий span-F1 (узкая разметка, IoU ≥ 0,5) | **0,717** | то же |
| Полнота по покрытию | 0,573 | то же |
| Ширина фрагмента | **×1,1** | то же |
| Вердикт: precision / recall / F1 | 0,992 / 0,388 / 0,558 | то же |

Демонстрационный корпус (240 пар, групповой сплит): token F1 0,953, FPR 0,002,
критерий качества (token F1 ≥ 0,90 при FPR ≤ 0,10) **достигнут**. Корпус
синтетический: эти числа подтверждают работоспособность конвейера, а не
качество на реальных документах.

Ложные замечания на чистых парах корпуса A: **0,000** (было 0,136).

Режим `hf`: **прогонов нет** (`hf_runs = 0`). Причина: в среде разработки нет
GPU, а доступ к весам моделей закрыт. При запросе режима `hf` без зависимостей
программа возвращает код 2 и явное сообщение, а не подменяет режим на `demo`.

## 7. Ограничения

* Режим `demo` не является научным результатом: это лексические суррогаты.
* Метод чувствителен к перефразированию: на корпусе другого генератора token F1
  0,717 при FPR 0,157; на внешних наборах 0,10–0,20.
* Тип `missing` не обнаруживается (recall 0,000); механизм покрытия фактов
  написан, но отключён: он давал больше ложных замечаний, чем находок.
* Максимальная длина текста, размеры файлов и время обработки — **не измерены**
  (`null`): функциональные испытания не проводились.

## 8. Контрольный пример

```
python -m spanverify verify \
  --answer "Срок хранения первичных документов составляет 3 года." \
  --context "Регламент 343: срок хранения первичных документов составляет 10 лет."
```

Ожидается: код возврата 1, вердикт `likely_hallucination`, фрагмент — «3 года».
