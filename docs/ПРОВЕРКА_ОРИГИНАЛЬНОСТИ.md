# Процедура проверки оригинальности отчёта о НИР

Договор № 20478ГУ/2026 (проект 117812), Приложение № 10, п. 4: «Процент
оригинальности текста Отчета должен быть не менее 80 %». Проверка выполняется во
внешней системе — из репозитория её сделать нельзя, поэтому этот пункт закрывает
получатель гранта. Здесь описано, что именно и куда внести.

## Что проверяется

Текст отчёта о выполнении НИР (промежуточного или заключительного), собранного по
Приложению № 10 из `docs/ОТЧЁТ_о_НИР_шаблон.md`. В счёт идёт основная часть
отчёта; титульный лист генерируется в АС «Фонд-М» автоматически и в проверку не
входит.

## Порядок действий

1. Экспортировать отчёт в формат, который принимает система проверки: `.docx`
   (`python tools/md_to_docx.py docs/ОТЧЁТ_о_НИР_шаблон.md`) или `.pdf`.
2. Проверить текст во внешней системе (например, «Антиплагиат», система вуза или
   система Фонда, если она предоставляется). Итоговая величина — **процент
   оригинальности по отчёту целиком**.
3. Сравнить с требованием: не менее 80 %.
4. Внести фактический процент в реестр чисел — файл `reports/NUMBERS.json`,
   запись `report.originality_percent`:
   - `value` — фактический процент из отчёта системы проверки;
   - `source` — файл-справка системы проверки (сохранить её в проектном архиве);
   - `commit` — коммит состояния отчёта, который проверялся;
   - `date` — дата проверки.
5. Запустить `python scripts/build_numbers.py` — реестр пересоберётся, и проверка
   `report.originality` в `python scripts/contract_check.py` покажет статус
   «соответствует», если процент не ниже 80.

## Почему сейчас «не измерено»

В репозитории процент оригинальности не проставлен: для его получения нужна
внешняя система проверки, которой в окружении прогона нет. Пока величины нет,
проверка `report.originality` честно показывает «не измерено» с указанием причины
— оценка или «примерно» здесь запрещены правилом чисел проекта.

## Что важно не сделать

* Не подставлять в реестр ожидаемое значение вместо измеренного.
* Не менять требование 80 % — это требование договора, а не настройка.
* Не удалять из отчёта разделы с ограничениями и отрицательными результатами ради
  процента оригинальности: они защищают проект на приёмке.
