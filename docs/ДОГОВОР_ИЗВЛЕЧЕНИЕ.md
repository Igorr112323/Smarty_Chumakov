# Извлечение из договора о предоставлении гранта (проект № 117812)

**Что это за файл.** Содержательная часть подписанного договора — только та, из
которой вытекают требования к работе: техническое задание, календарный план,
правила отчётности и сроки. Файл нужен, чтобы требования были доступны читателю
репозитория, а подписанный PDF с персональными данными в публичном репозитории
не хранился (см. «Что не перенесено» ниже).

**Источник.** `Договор_0117812 (25).pdf` — 32 страницы, 5 019 351 байт,
SHA-256 `e5eb6ad8522fa70135f75bf22b0b5f3464fcc17d9c6f04d81b48976a42e69cd5`.
Текст извлечён программно (pypdf) командой:

```bash
python -c "from pypdf import PdfReader; print('\n'.join((p.extract_text() or '') for p in PdfReader('Договор_0117812 (25).pdf').pages))"
```

**Реквизиты (без персональных данных).** Договор (соглашение) № 20478ГУ/2026,
г. Москва, 13 октября 2026 г. Грантодатель — Федеральное государственное
бюджетное учреждение «Фонд содействия развитию малых форм предприятий в
научно-технической сфере» (Фонд содействия инновациям). Получатель гранта —
физическое лицо; его персональные данные в этот файл не переносятся. Конкурс —
«УМНИК-2026 (очередь 1)». Проект № 117812 (в PDF встречается также как 0117812).

**Тема НИР** (п. 1.1 договора, Приложение № 3): «разработка программного модуля
span-уровневой верификации контента с определением доли участия ии для
корпоративных систем».

## 1. Техническое задание (Приложение № 3, стр. 11–13)

Цель: разработка метода и программного продукта для локальной проверки
соответствия русскоязычного ответа документу-источнику с выделением
неподтверждённых фрагментов и расчётом оценки риска.

Задачи (п. 2 ТЗ): методика разметки пар «документ — ответ»; информативность
признаков внимания языковой модели и контекстных векторных представлений;
алгоритм объединения признаков, риска по токенам и границ спорных фрагментов;
оценка качества и устойчивости на независимых по документам выборках (F1, FPR,
локализация фрагментов); лабораторный образец и его функциональные испытания.

### 1.1 Числовые требования (п. 4.1, «Характеристики» 1–9, стр. 11–12)

| № | Требование (формулировка договора) | Значение |
| --- | --- | --- |
| 1 | Входные данные — текст документа и текст ответа в UTF-8 | максимум **2 000 000 знаков** |
| 2 | Выходные данные — оценка риска и список фрагментов с координатами (номера первого и последнего символа), меткой и уровнем уверенности | риск **от 0 до 1**, уверенность **от 0 до 1** |
| 3 | Признаки на токен, включая энтропию внимания, долю внимания на документ и косинусную близость векторных представлений | **пять** числовых признаков |
| 4 | Оценка доли участия языковой модели с калибровкой на наборе с известной долей смеси текстов | **от 0 до 1**, шаг смеси **0,25** |
| 5 | Показатели качества — precision, recall, F1 и доля ложных срабатываний по токенам, ответам и фрагментам при пересечении границ | пересечение границ **не ниже 0,5** |
| 6 | Целевой ориентир на отложенной по документам части набора | **F1 не ниже 0,50** при **FPR не выше 0,40**, набор **1200 пар** |
| 7 | Быстродействие | **не более 0,03 с на 1 000 знаков**; **2 000 000 знаков — не более 60 с**; **50 000 знаков — не более 1 с** (п. 4.2, стр. 13) |
| 8 | Интерфейсы | командная строка, локальный веб-интерфейс, программный интерфейс HTTP |
| 9 | Поставка | автономный файл для Windows и переносимый пакет для Python 3.10 и выше |

Обращений к внешним сервисам не будет (п. 4.1); сверка фрагментов с
первоисточником и решение о нарушении остаются за пользователем (п. 4.2).

### 1.2 Конструктивные требования (п. 4.2, стр. 12–13)

* Поставка: один исполняемый файл под Windows 10 и новее объёмом **не более
  9 МБ** либо переносимый пакет объёмом **не более 0,6 МБ** для Python 3.10+.
* Интерфейс: локальный веб-интерфейс по адресу **http://localhost:8765**;
  установка в систему не требуется, изменения в реестр не вносятся, службы не
  регистрируются.
* Сборка: автоматически из исходного кода на сервере непрерывной интеграции;
  результат проходит проверку, файл сопровождается контрольной суммой **SHA-256**.
* Режим признаков языковой модели: библиотеки Python объёмом **около 500 МБ** и
  файл весов модели объёмом **около 530 МБ**, сохраняемые локально заранее.
* Хранение: **не более 100 МБ** без весов модели и **не более 1,5 ГБ** с весами;
  документы пользователя в поставку не входят; целостность — сверкой SHA-256.
* Транспортировка: копированием на разрешённый носитель, специальная маркировка
  не требуется, перед установкой контрольная сумма сверяется организацией.
* Эксплуатация: процессор **x86-64**, ядер **не менее двух**, оперативная память
  **не менее 4 ГБ** (**не менее 8 ГБ** с весами модели), свободное место на
  диске **не менее 1,5 ГБ**; видеокарта и внешний сетевой доступ не потребуются.
* Обновление: заменой файла и файлов весов целиком, предыдущая версия сохраняется
  до проверки новой.
* Прочее: п. 5 — патентная защита (часть четвёртая ГК РФ); п. 6 — получатель
  гранта должен быть автором или входить в число авторов РИД; п. 7 — отчётность по
  Приложению № 10; п. 8 — срок выполнения работ **12 месяцев**.

## 3. Правила оформления отчёта (Приложение № 10, стр. 23–26)

Структурные элементы отчёта (п. 1): титульный лист; реферат; содержание;
термины и определения; перечень сокращений и обозначений; введение; основная
часть; заключение; список использованных источников; приложения — всего
**10 элементов**.

* Титульный лист генерируется в АС «Фонд-М» автоматически (п. 2.1).
* Реферат (п. 2.2): сведения об общем объёме отчёта, числе иллюстраций, таблиц,
  использованных источников, приложений; **перечень ключевых слов от 5 до 15**
  слов или словосочетаний; текст реферата — оптимально 850 печатных знаков, но не
  более одной страницы (стр. 24).
* Содержание (п. 2.3) — наименования всех элементов с номерами страниц.
* Основная часть (п. 2.7): названия разделов совпадают с названиями работ
  календарного плана; официально-деловой стиль; описание выполнения каждой работы
  отчётного этапа и её результатов.
* Заключение (п. 2.8): краткие выводы и оценка полноты решения поставленных задач.
* **Процент оригинальности текста отчёта — не менее 80 %** (п. 4, стр. 26).

Приложение № 11 (стр. 27–29) — рекомендации к бизнес-плану проекта (объём не
менее 20 страниц); Приложение № 12 (стр. 30–31) — рекомендации к дорожной карте
развития проекта. Оба документа — зона получателя гранта, к коду не относятся.

## 4. Что не перенесено (персональные данные)

В этот файл **не переносятся**: ФИО получателя гранта (оно напечатано на каждой
странице PDF), паспортные данные, ИНН, адрес регистрации, банковские реквизиты
(лицевой счёт, БИК, корреспондентский счёт, наименование банка) и подписи сторон
(стр. 32, «Адреса и банковские реквизиты сторон»). Эти сведения остаются только в
подписанном PDF, который в публичном репозитории не хранится. Для проверок в
репозитории остаётся **только SHA-256 файла** — по нему версия источника
фиксируется, а сами данные не раскрываются. Явное согласие на обработку
персональных данных (Приложение № 6) также не переносится.
