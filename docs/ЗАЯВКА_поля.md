# Поля заявки в АС «Фонд-М»: готовые формулировки

Документ — для копирования в поля заявки. Формулировки проверены на
соответствие требованиям к научно-исследовательским работам: в описании этапов
нет видов работ, которые к НИР не относятся.

---

## 1. Команда и роль продукта

**Название проекта (полное):** Инструмент проверки достоверности текста по
документу-источнику на основе анализа внимания языковой модели (SpanVerify).

**Формулировка проблемы.** Генеративные языковые модели всё чаще используются для
подготовки ответов по документам: справок, выписок из регламентов, обобщений
инструкций. Такие тексты бегло выглядят достоверно даже тогда, когда числа,
сроки и ссылки в них не соответствуют источнику. Ручная выборочная проверка
несистематична, а инструментов, которые бы показывали **где именно** ответ
расходится с документом, для русскоязычных текстов почти нет.

**Что предлагается.** Метод и программное средство, которые получают документ и
ответ, вычисляют по токенам ответа признаки на основе внимания языковой модели и
векторных представлений, формируют оценку риска, выделяют связные фрагменты с
риском выше порога и выдают количественную оценку достоверности ответа. Работает
локально: тексты не покидают компьютер пользователя.

## 2. Научная новизна (формулировка для поля)

Постановка задачи как локального сопоставления ответа с конкретным документом:
средство указывает фрагменты ответа, не подтверждённые источником, а не только
оценивает текст целиком. Признак доли внимания на документ используется с
отрицательным знаком (больше опоры — меньше риска) и сопоставляется с «сырой»
энтропией внимания на нескольких слоях модели. Параметры метода калибруются по
целевому уровню ложных срабатываний, что делает результат пригодным для решений,
где цена ложного обвинения высока.

## 3. Метод (для поля «содержание работы»)

1. Токенизация ответа с сохранением смещений в символах.
2. Признаки на токен: нормированная энтропия внимания; доля массы внимания,
   приходящаяся на документ; плотность близости представлений токена к
   ближайшим токенам документа (базовый уровень без использования внимания).
3. Взвешенная комбинация признаков с подбором весов по AUC на обучающей части
   (перебор сетки, сумма весов равна единице).
4. Оценка ответа как полусуммы среднего риска и среднего риска верхних
   двадцати процентов токенов; изотоническая калибровка (PAVA).
5. Порог решения выбирается по целевому уровню ложных срабатываний на
   обучающей части; тестовая часть используется только для измерения.

## 4. Планируемые результаты

1. Обученный метод с открытыми параметрами (`weights.json`: веса, пороги,
   калибровка, решающая голова).
2. Программное средство: локальное приложение для Windows одним файлом,
   HTTP-интерфейс, интерфейс командной строки.
3. Протокол оценки: метрики по токенам и фрагментам, доверительные интервалы
   бутстрэпом, сравнение признаков по слоям модели.
4. Комплект документации: руководство пользователя, описание метода, отчёт о
   НИР, руководство по обучению на собственных размеченных парах.

## 5. Формулировки для коротких полей

**Аннотация (до 500 знаков).** Работа посвящена проверке достоверности текста по
документу-источнику. Предлагается метод, который по вниманию языковой модели и
близости представлений вычисляет риск недостоверности каждого токена ответа,
выделяет связные фрагменты, не подтверждённые документом, и выдаёт оценку
достоверности ответа. Параметры калибруются по целевому уровню ложных
срабатываний. Реализовано локальное приложение для Windows (один файл),
HTTP-интерфейс и интерфейс командной строки; проведена оценка на размеченных
парах и пилотное исследование признаков по слоям реальной модели.

**Актуальность (до 300 знаков).** Генеративные модели готовят ответы по
документам, и правдоподобные по форме ответы могут содержать неподтверждённые
числа, сроки и ссылки. Инструментов локальной проверки ответа относительно
конкретного документа для русскоязычных текстов недостаточно.

**Практическая значимость (до 300 знаков).** Средство применимо для выборочной
проверки ответов справочных систем и сотрудников по регламентам. Работает
локально, тексты не передаются во внешние сервисы; результат указывает места для
перечитки, а не выносит автоматический приговор.

**Ограничения (обязательно указать честно, до 300 знаков).** Качество зависит от
модели и предметной области; нужна калибровка на размеченных парах пользователя.
Демонстрационный корпус синтетический: его метрики подтверждают
работоспособность метода, но не качество на реальных документах.

## 6. Что заполняет исполнитель (данные извне)

| Поле | Кто заполняет | Комментарий |
| --- | --- | --- |
| Публикации по теме | исполнитель | перечислить статьи/тезисы, если есть |
| Дипломная работа | исполнитель | тема, научный руководитель, организация |
| Письмо поддержки | исполнитель | например, от организации-партнёра |
| Сроки этапов | исполнитель | в календарном плане указаны относительные сроки |
| Стоимость работ | исполнитель | при требовании конкурсной документации |

## 7. Чего в заявке быть не должно

Ниже — виды работ, которые не относятся к НИР; в текст заявки и календарного
плана они не включались: производство, изготовление, опытный или промышленный
образец, опытная партия, сертификация, упаковка, маркетинг, продвижение,
конструкторская и технологическая документация, закупка оборудования,
клинические испытания, патентование и подача заявки на патент как вид работы,
литературный обзор как отдельный этап, публикация статьи и участие в
конференции как обязательный результат, преакселерация, бизнес-план.

## 8. Соответствие фактическому состоянию работы

На момент оформления заявки: метод реализован, обучен и откалиброван; проведена
оценка на отложенной части демонстрационного корпуса (token F1 0.959 при
FPR 0.002, критерий F1 ≥ 0.90 при FPR ≤ 0.10 выполнен); проведён пилот на
реальной модели `rugpt3small` в режиме вычислений на CPU с парным анализом
признаков по слоям; приложение собрано, проверено автоматическим смоук-тестом и
опубликовано по постоянной ссылке. Полные данные — в `ИТОГ.md` и
`docs/ОТЧЁТ_о_НИР_шаблон.md`.
