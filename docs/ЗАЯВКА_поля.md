# Поля для заявки в АС «Фонд-М»: готовые формулировки

Текст подготовлен так, чтобы его можно было копировать в поля заявки без
правки. Все формулировки — научно-исследовательские (без слов о производстве,
сертификации, продвижении, закупках и патентовании: эти виды работ в
календарный план не включаются).

---

## 1. Название проекта

**Разработка и исследование метода автоматического выявления недостоверных
фрагментов текста на основе сопоставления ответа с документом-источником**

Короткое название (для интерфейсов и презентаций): **SpanVerify**.

## 2. Направление

Информационные технологии, искусственный интеллект, обработка естественного
языка; инструменты контроля качества текстов, порождаемых генеративными
моделями.

## 3. Аннотация (до 800 знаков)

Проект посвящён задаче, которая возникает при практическом применении
генеративных языковых моделей: модель уверенно выдаёт утверждения, которые не
подтверждаются источником — числовые значения, сроки, ссылки на нормы.
Предлагается метод проверки ответа относительно документа-источника: по каждому
токену ответа вычисляются признаки (энтропия внимания модели, доля внимания на
документ, плотность близости к фрагментам документа), из них формируется оценка
риска, а найденные участки объединяются в связные фрагменты с метками
«сомнительно» и «высокий риск». Метод откалиброван по целевому уровню ложных
срабатываний, реализован в виде программы и HTTP-интерфейса, проверен на
контрольном наборе пар «документ — ответ». Результат — инструмент, который
показывает человеку места, требующие перечитки, и количественно описывает
степень опоры ответа на источник.

## 4. Актуальность

Генеративные модели всё шире применяются для подготовки справок, ответов на
запросы и обобщений документации. Ошибки в таких текстах (подмена числовых
значений, ссылки на несуществующие положения) обнаруживаются человеком
несистематически: на глаз правдоподобный текст выглядит корректным.
Существующие средства либо оценивают «похожесть на ИИ» без обращения к
источнику, либо требуют разметки больших корпусов. Задача сопоставления ответа
с конкретным документом и локальный поиск неподтверждённых мест исследована
недостаточно, особенно для русскоязычных текстов.

## 5. Цель и задачи

**Цель:** разработать метод выявления неподтверждённых документом фрагментов
ответа и оценить его качество на размеченных данных.

**Задачи исследования:**

1. Обзор существующих подходов к проверке фактической опоры текста на источник
   и уточнение постановки задачи для русскоязычных документов.
2. Разработка признаков недостоверности на основе внимания языковой модели и
   векторных представлений.
3. Разработка схемы агрегации признаков: оценка риска по токенам, выделение
   связных фрагментов, оценка достоверности ответа в целом.
4. Обучение и калибровка параметров метода по целевому уровню ложных
   срабатываний.
5. Экспериментальная оценка метода: метрики по токенам и фрагментам, сравнение
   признаков между собой и по слоям модели.
6. Разработка программной реализации (локальное приложение и HTTP-интерфейс) и
   её апробация на контрольных примерах.

## 6. Научная новизна и значимость

* Постановка задачи как локального сопоставления: метод указывает **где** ответ
  расходится с документом, а не только «достоверен / недостоверен».
* Признак доли внимания на документ используется со знаком «чем больше опора,
  тем ниже риск» и сравнивается с классической энтропией внимания по слоям
  модели — гипотеза проверяется экспериментально, а не постулируется.
* Метод калибруется по целевому уровню ложных срабатываний, что делает его
  применимым там, где цена ложного обвинения высока.
* Все параметры метода воспроизводимы: фиксированный seed, открытые скрипты
  обучения и оценки, сохранение параметров в текстовом файле.

## 7. Практическая значимость

Инструмент применим для выборочной проверки ответов справочных систем,
сгенерированных обзоров документации, ответов сотрудников по регламентам.
Работает локально: документы не передаются во внешние сервисы, что важно для
внутренних регламентов и персональных данных. Результат выдаётся как указание
на фрагменты для перечитки, а не как автоматический приговор.

## 8. Методы и инструменты

* Языковая модель `ai-forever/rugpt3small_based_on_gpt2` (CPU-вычисления);
* признаки внимания и скрытых состояний; косинусная близость представлений;
* логистическая регрессия с кросс-валидацией; изотоническая калибровка (PAVA);
* метрики: precision, recall, F1 по токенам и фрагментам, FPR, AUC,
  доверительные интервалы бутстрэпом;
* Python 3.10+, GitHub Actions для воспроизводимых сборок и проверок.

## 9. Ожидаемые результаты

1. Метод и его программная реализация с открытыми параметрами обучения.
2. Количественная оценка качества на контрольном наборе: token F1 и FPR при
   фиксированном целевом уровне ложных срабатываний.
3. Сравнительный анализ признаков, включая разбиение по слоям модели.
4. Комплект документации: описание метода, руководство пользователя, отчёт о
   НИР, календарный план.
5. Публикация промежуточных результатов (при наличии у исполнителя
   публикационной активности — указывает исполнитель).

## 10. Ограничения и риски (честно)

* Качество метода зависит от модели и предметной области; требуется
  калибровка на размеченных парах пользователя.
* Синтетический демонстрационный корпус не заменяет реальную разметку: числа
  на нём характеризуют работоспособность метода, а не качество на реальных
  документах.
* Сроки и объём зависят от доступа к вычислительным ресурсам для режима
  реальной модели.

## 11. Что заполняет исполнитель (данные извне)

* **Публикации** по теме (при наличии).
* **Дипломная работа / квалификационная работа**: тема, научный руководитель,
  организация.
* **Письмо поддержки** от организации (например, ООО «Вебпрактик»): реквизиты,
  подпись, дата.
* **Сроки этапов**: уточняются по регламенту конкурса.
* **Объём финансирования** (если требуется конкурсной документацией).

## 12. Состав команды и роли

Заполняется исполнителем: руководитель проекта, исследователь, разработчик,
консультант по предметной области. В заявке достаточно указать функции
(постановка задачи, реализация метода, проведение экспериментов, подготовка
отчётности).

## Короткие формулировки для полей с ограничением длины

**Ожидаемый результат (до 300 знаков).** Метод выявления неподтверждённых
документом фрагментов ответа и его программная реализация; количественная
оценка качества на размеченных парах (token F1, FPR при целевом уровне ложных
срабатываний); руководство пользователя и отчёт о НИР.

**Научная новизна (до 300 знаков).** Локальное сопоставление ответа с
документом: метод указывает конкретные неподтверждённые фрагменты, использует
признак доли внимания на документ и калибруется по целевому уровню ложных
срабатываний.

**Метод (до 300 знаков).** Признаки внимания языковой модели и векторной
близости по токенам ответа → оценка риска → выделение связных фрагментов →
калибровка по целевому FPR; оценка на контрольном наборе с бутстрэп-интервалами.
