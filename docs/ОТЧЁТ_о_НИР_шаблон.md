## 1. Введение

Работа посвящена проверке достоверности текста относительно
документа-источника. Практическая потребность: ответы, подготовленные по
документам (справки, выписки из регламентов, обобщения инструкций), могут
содержать числа, сроки и ссылки, которых в источнике нет, при этом внешне текст
выглядит достоверным. Ручная проверка несистематична, а существующие средства
либо оценивают «похожесть на машинный текст» без обращения к документу, либо
требуют обращения к внешним базам знаний.

## 2. Постановка задачи

Дано: документ (контекст) $C$ и ответ $A$. Требуется:

1. получить по каждому токену ответа оценку риска недостоверности;
2. выделить связные фрагменты ответа, не подтверждённые документом, и указать
   их метки;
3. получить оценку достоверности ответа в целом с порогом, обеспечивающим
   заданный уровень ложных срабатываний.

Ограничение: обработка выполняется локально, без внешних сервисов.

## 3. Обзор подходов

Рассматриваются три группы методов: (а) определение «написан ли текст моделью»
без обращения к источнику; (б) проверка опоры текста на источник через внешние
хранилища фактов; (в) локальные методы на основе внутренних сигналов языковой
модели (внимание, представления). Работа развивает третью группу: она не требует
внешних баз знаний и позволяет указать конкретные неподтверждённые фрагменты.

## 4. Метод

### 4.1. Признаки (по токенам ответа, диапазон [0, 1])

1. **Нормированная энтропия внимания** выбранного слоя — мера размытости
   распределения внимания.
2. **Доля массы внимания на документ** — суммарное внимание токена к позициям
   контекста. Входит в риск с **отрицательным** знаком: больше опоры — меньше
   риска.
3. **Плотность близости представлений** — среднее косинусное сходство
   представления токена с $k$ ближайшими токенами контекста (базовый уровень без
   использования внимания).

### 4.2. Агрегация

$r = w_1 \hat{H} + w_2 (1 - \hat{m}) + w_3 \hat{d}$; веса подбираются перебором по
сетке с суммой 1 по AUC на обучающей части. Далее: центрированное сглаживание
окном 3 с весом центра 0.6 (сохраняет узкие подмены); порог маски
$T = \mu + z \cdot \sigma$, ограниченный снизу и сверху; склейка соседних
помеченных токенов; расширение до границ предложения; метка
`likely_hallucination` при риске ≥ 0.75, иначе `doubtful`.

Несодержательные токены (пунктуация и короткие служебные слова) исключаются из
оценки риска и из метрик: их нельзя «выдумать», и они не должны размывать
соседние пики.

### 4.3. Оценка ответа, калибровка, обучение

Оценка ответа $s = 0.5 \cdot \overline{r} + 0.5 \cdot \overline{r}_{top20\%}$.
Калибровка — изотоническая регрессия (PAVA). Порог решения — по целевому уровню
ложных срабатываний **на обучающей части**; тестовая часть не используется для
подбора порога. Дополнительно обучается решающая голова (логистическая регрессия
по признакам токена с 5-кратной кросс-валидацией) и применяется только в том
случае, если превосходит пороговое правило по F1 при том же ограничении на FPR.

## 5. Программное средство

* Ядро — стандартная библиотека Python 3.10+ (без обязательных зависимостей).
* Режимы: `demo` (лексические суррогаты признаков) и `hf` (реальная модель
  `torch` + `transformers`).
* Интерфейсы: HTTP (`POST /v1/verify`, `GET /health|/v1/config|/v1/model`, `/`),
  командная строка (`verify`, `train`, `calibrate`, `evaluate`, `selftest`,
  `server`, `demo`, `analyze`), встроенная веб-страница.
* Приложение для Windows — один файл; параметры метода упакованы внутрь, при
  запуске без папки `config/` используются встроенные (проверяется в CI).

## 6. Данные, метрики и процедура оценки

* **Демонстрационный набор:** 240 пар «документ — ответ» трёх типов
  (подтверждённый ответ, подмена числового значения, выдуманное утверждение),
  разметка по символам ответа; разделение 70/30 по парам (seed 42).
  Набор **синтетический** — это ограничивает выводы.
* **Метрики:** precision, recall, F1 по токенам, FPR, AUC; полнота накрытия
  фрагментов и F1 по фрагментам при расширенной разметке; метрики уровня ответа.
* **Пилот:** контрастные пары «с опорой»/«без опоры»; в каждой паре ответы
  совпадают по шаблону и отличаются **одним числом** (трудный случай). Признаки
  считаются реальной моделью `ai-forever/rugpt3small_based_on_gpt2` на CPU;
  анализ — по слоям (`first`, `middle`, `-4`, `last`) с доверительными
  интервалами методом бутстрэпа (5000 итераций) и **парным** сравнением
  (разница внутри пары, что исключает вариативность жанра).

## 8. Обсуждение

Работа показывает, что задача локализации неподтверждённых фрагментов решается
на выбранном классе искажений (подмена значения, выдуманное утверждение) в
демонстрационном режиме и **не решается** признаками внимания небольшой модели в
предельно трудной постановке «одно число». Это содержательный результат: он
разграничивает «работоспособность конвейера» и «научную состоятельность
признаков» и определяет направление дальнейших исследований — более крупные
модели, более сильные искажения, обучение на реальных размеченных парах.

## 9. Ограничения

1. Демонстрационный набор синтетический; метрики раздела 7.1 отражают
   работоспособность и самосогласованность метода.
2. Пилот ограничен одной моделью и десятками пар; доверительные интервалы
   широкие (см. артефакт).
3. Признаки зависят от выбора модели и слоя.
4. Для прикладного применения нужна калибровка на размеченных парах пользователя
   (процедура описана в руководстве).
5. На реальных актах (раздел 7.3) ориентир «F1 ≥ 0.90 при FPR ≤ 0.10» не
   достигнут; по чистым парам теста вердикт помечает 0.80 ответов.

## 10. Заключение

Разработан и исследован метод локализации неподтверждённых документом
фрагментов ответа, реализовано программное средство с локальной обработкой,
проведены оценка на отложенной части демонстрационного набора и пилотное
исследование признаков по слоям реальной модели. Задачи этапов 1–7 календарного
плана выполнены; полученный отрицательный результат пилота зафиксирован и
определяет направления дальнейшей работы.
