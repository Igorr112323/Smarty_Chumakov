# Отчёт о научно-исследовательской работе (шаблон с заполненными разделами)

**Тема:** разработка и исследование метода автоматического выявления
недостоверных фрагментов текста на основе сопоставления ответа с
документом-источником.

**Исполнитель:** заполняется. **Срок выполнения:** заполняется.
**Объём работы:** этапы 1–7 календарного плана (`docs/ТЗ_и_календарный_план.md`).

> Разделы 1–3 — вводные, заполняются по образцу. Разделы 4–11 содержат
> фактическое описание выполненной работы и должны быть выверены по
> `PROGRESS.md` и `ИТОГ.md` перед подписанием: числа берутся только из
> артефактов запусков.

---

## 1. Введение

Работа посвящена задаче проверки достоверности текста относительно
документа-источника. Актуальность определяется практикой применения
генеративных моделей: правдоподобные по форме ответы могут содержать
неподтверждённые значения (сроки, числа, ссылки на нормы), а выборочная
проверка вручную несистематична.

## 2. Постановка задачи

Дано: документ-контекст $C$ и ответ $A$. Требуется:

1. для каждого фрагмента ответа получить оценку риска недостоверности;
2. выделить связные фрагменты, не подтверждаемые документом;
3. получить оценку достоверности ответа в целом и порог решения,
   обеспечивающий заданный уровень ложных срабатываний.

Ограничение: метод не должен требовать внешних сервисов; обработка выполняется
локально.

## 3. Обзор подходов

Рассматриваются три семейства методов: (а) оценка «написан ли текст моделью»
без обращения к источнику; (б) проверка опоры текста на источник по внешним
инструментам поиска фактов; (в) локальные методы на основе представлений и
внимания языковой модели. Работа развивает третье направление: оно не требует
внешних баз знаний и позволяет указать конкретные неподтверждённые фрагменты.

## 4. Метод

### 4.1. Признаки

По каждому токену ответа вычисляются три признака в диапазоне [0, 1]:

1. **Нормированная энтропия внимания** последнего (или заданного) слоя модели —
   мера «неуверенности» распределения внимания токена.
2. **Доля внимания на документ** — суммарная масса внимания токена на позиции
   контекста. Входит в риск с обратным знаком: чем выше опора на источник, тем
   ниже риск.
3. **Плотность близости представлений** — среднее косинусное сходство
   представления токена с ближайшими токенами контекста (базовый уровень без
   использования внимания).

### 4.2. Агрегация

Риск токена: $r = w_1 \hat{H} + w_2 (1 - \hat{m}) + w_3 \hat{d}$, где веса
подбираются перебором по сетке с суммой 1 на валидационной части по AUC
токенного уровня. Далее: сглаживание по окну 3; порог маски как устойчивая
оценка центра и разброса распределения рисков, ограниченная снизу и сверху;
склейка соседних помеченных токенов; расширение фрагмента до границ
предложения; метка `likely_hallucination` для риска выше фиксированного уровня,
иначе `doubtful`.

### 4.3. Оценка ответа и калибровка

Оценка ответа: $s = 0.5 \cdot \overline{r} + 0.5 \cdot \overline{r}_{\text{top 20\%}}$
(учитывает и общий уровень, и выраженные пики). Калибровка — изотоническая
регрессия (алгоритм PAVA) на обучающей части; порог решения выбирается как
максимум F1 при ограничении FPR, то есть порог **не подбирается по тестовой
выборке**.

### 4.4. Обучение

Дополнительно обучается решающая голова (логистическая регрессия по признакам
токена с 5-кратной кросс-валидацией). Голова применяется только в том случае,
если на обучающей части она превосходит пороговое правило по F1 при том же
ограничении на FPR; иначе используется правило, и это фиксируется в отчёте.

## 5. Программная реализация

* Ядро — стандартная библиотека Python 3.10+ (без обязательных зависимостей).
* Режимы: `demo` (лексические суррогаты признаков, без весов модели) и `hf`
  (реальная модель через `torch`/`transformers`).
* Интерфейсы: HTTP (`POST /v1/verify`, `GET /health|/v1/config|/v1/model`, `/`),
  командная строка (`verify`, `train`, `calibrate`, `evaluate`, `selftest`,
  `server`), веб-страница для ручной проверки.
* Приложение для Windows собирается в один файл и проверяется автоматическим
  смоук-тестом перед публикацией.

## 6. Данные и методика оценки

* Демонстрационный контрольный набор: 240 пар «документ — ответ» трёх типов
  (подтверждённый ответ, подмена значения, выдуманное утверждение) с разметкой
  по символам ответа. Набор синтетический, что прямо ограничивает выводы.
* Разделение на обучающую и отложенную части по парам; метрики считаются только
  на отложенной части.
* Метрики: precision, recall, F1 по токенам; FPR; AUC; F1 по фрагментам и
  полнота накрытия; метрики уровня ответа.
* Пилот на реальной модели: контрастные пары «с опорой» / «без опоры» с
  различием ровно в одном числе; проверка контраста; AUC признаков с 95 %
  доверительным интервалом (бутстрэп, 5000 итераций) по слоям модели.

## 7. Результаты

### 7.1. Качество на отложенной части (демонстрационный режим)

| Метрика | Значение |
| --- | --- |
| token F1 | 0.959 |
| token precision | 0.988 |
| token recall | 0.932 |
| FPR по токенам | 0.002 |
| AUC по токенам | 0.996 |
| полнота накрытия фрагментов | 1.000 |

Критерий приёмки (token F1 ≥ 0.90 при FPR ≤ 0.10) выполнен. Числа получены
сквозным путём — той же функцией, которую вызывает HTTP-интерфейс.

### 7.2. Пилот на реальной модели

Результаты приводятся по артефакту `reports/pilot/pilot.md` из автоматического
запуска (джоба `pilot`). В отчёте фиксируются: характеристики контраста групп,
таблица AUC с доверительными интервалами по слоям, вывод о том, подтвердилась
ли гипотеза о превосходстве признака доли внимания на документ над энтропией
внимания.

> При оформлении вставить числовые значения и дату запуска из артефакта.

### 7.3. Апробация приложения

Автоматический смоук-тест на сборочном раннере: запуск приложения, проверка
работоспособности, запрос на подмену значения (фрагмент найден, метка
«сомнительно»/«высокий риск»), запрос на подтверждённый ответ (вердикт
«ответ подтверждается документом»), проверка справочных маршрутов и веб-страницы.

## 8. Обсуждение

Полученные результаты показывают, что признаки внимания языковой модели
позволяют локализовать подмену значения в пределах предложения при низкой доле
ложных срабатываний. Ограничения: контрольный набор синтетический; замена
значения — наиболее простой для обнаружения случай; фрагменты выдаются с
расширением до границ предложения, что удобно человеку, но снижает строгие
метрики перекрытия с узкой разметкой (в отчёте приводятся обе характеристики).

## 9. Ограничения и достоверность выводов

1. Демонстрационные числа описывают работоспособность и самосогласованность
   метода, а не качество на реальных документах.
2. Результаты пилота получены на малом объёме с широкими доверительными
   интервалами.
3. Модель одна и небольшая; при смене модели признаки могут вести себя иначе.
4. Для практического применения требуется калибровка на размеченных парах
   пользователя.

## 10. Заключение

Разработан и исследован метод выявления неподтверждённых документом фрагментов
ответа: определены признаки, схема агрегации, процедура обучения и калибровки;
реализовано приложение с локальной обработкой данных; выполнена оценка на
отложенной части контрольного набора и пилотное исследование на реальной
русскоязычной модели. Задачи этапов 1–7 календарного плана выполнены.
