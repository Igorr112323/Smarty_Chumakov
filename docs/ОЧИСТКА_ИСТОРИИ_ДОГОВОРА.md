### Шаг 2: запушить переписанную историю

Вариант Б — повторить перепись штатным скриптом (результат детерминирован, новые

### Шаг 4: обращение в поддержку GitHub

GitHub хранит объекты, на которые ссылаются **серверные ссылки pull request'ов**
(`refs/pull/1…9/head`): пуш их не переписывает — такие ссылки сервер не принимает,
они остаются у GitHub. Пока они живы, старые коммиты достижимы, а с ними и blob
PDF. После сборки мусора недостижимые объекты исчезнут, но на это нельзя
рассчитывать. В локальной переписанной копии `mirror/` эти же девять ссылок уже
переписаны и PDF не содержат (`after_state.log`), однако на сервер такую правку
отправить нельзя — только через поддержку.

Поэтому после шага 2 напишите в GitHub Support (или через форму «Report content»)
запрос: удалить кэшированные представления объекта
`a52928f529b1496b68b0ce8e38477b6486bfd6af` (blob PDF) и коммита
`64c893081036fe2395c089eb41d7972e284b2548` в репозитории
`Igorr112323/Smarty_Chumakov`. Без этого шага очистку нельзя называть полной —
это ограничение платформы, а не недоделка репозитория.

## 4. Последствия переписи — знать до пуша

* Все существующие клоны разойдутся с сервером: соавторам нужно клонировать
  заново, а не делать `pull`/`merge`.
* 27 из 31 ссылки получают новые SHA; серверные ссылки PR (1–9) остаются на
  старых коммитах — их история на сервере станет недостижимой только после
  вмешательства поддержки, обсуждения PR сохраняются.
* Ветки `data/*` и `arena/*` — хвосты прошлых сессий; если они не нужны, их лучше
  удалить до переписи, чтобы не плодить сущности.
* Теги `v1.2.1` и `v1.3.0` не переписываются (в них PDF нет) — релизы и их
  SHA-256 остаются валидными; тег `v1.3.1` переписывается (в его истории PDF был),
  сам релиз и приложенные файлы при этом не меняются, контрольные суммы годны.
