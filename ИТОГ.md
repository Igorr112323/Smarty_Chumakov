## Проверка (7 строк — ваш финальный шаг)

1. Скачайте `spanverify.exe` из ссылки выше (около 9 МБ).
2. Сверьте хеш: `Get-FileHash .\spanverify.exe -Algorithm SHA256` — значение
   должно совпасть с первой строкой `SHA256SUMS.txt`. Если Windows показывает
   предупреждение SmartScreen (файл без подписи) — «Подробнее» → «Выполнить в любом случае».
3. Запустите двойным кликом: откроется чёрное окно с адресом и браузер с
   интерфейсом на `http://localhost:8000`.
4. Нажмите **«Пример: смешанный»** → **«Проверить достоверность»**.
5. Убедитесь, что машинные фрагменты подсвечены красным, есть доли участия ИИ
   (в символах и словах) и таблица найденных фрагментов.
6. Повторите с **«Пример: человеческий»** — фрагментов быть не должно.
7. Закройте окно консоли (или Ctrl+C) — сервер остановится.

Если что-то не сошлось — пришлите скриншот и вывод чёрного окна, разберёмся.

## Что умеет приложение

* Находит **где** в тексте машинные фрагменты: точные смещения в символах и
  токенах, средняя и пиковая вероятность для каждого фрагмента.
* Оценивает **долю участия ИИ** в символах и словах, выдаёт вердикт
  (`likely_ai` / `mixed` / `likely_human`).
* Работает **локально и офлайн**: интернет не нужен, текст никуда не уходит.
* Интерфейс в браузере, REST API (`/health`, `/v1/verify`, `/v1/config`,
  `/v1/model`), CLI (`analyze`, `demo`, `calibrate`, `serve`, `selftest`).

## Честные ограничения (важно для отчётности)

1. **В поставке демо-режим** (`surrogate`): он проверяет работоспособность
   конвейера и интерфейса, а **не** достоверность текста. Каждый ответ сервиса
   содержит это предупреждение.
2. **Числа качества на синтетическом корпусе** (токены F1 0.944, фрагменты
   F1 0.833, ошибка доли ИИ 0.141) получены на данных, порождённых одним
   генератором. В отчёт по договору их переносить нельзя.
3. **Боевой режим** `hf` (энтропия внимания последнего слоя + kNN контекстных
   эмбеддингов) реализован в коде, но требует установки `torch`/`transformers`
   и **вашего размеченного корпуса** — в этом окружении он не исполнялся.
4. **Windows-проверка проведена на раннере GitHub**, а не на вашем компьютере:
   финальный клик всё равно ваш (чек-лист выше).
5. Файл **не подписан** электронной подписью — возможен запрос SmartScreen.
6. Текст, прошедший ручную правку или пересказ моделью, распознаётся хуже;
   короткие тексты (1–2 предложения) оцениваются с высокой дисперсией.
7. Детектор даёт **вероятностную оценку**, а не доказательство авторства:
   использовать как единственное основание для решений нельзя.

## Технические заметки

* Релиз `v1.0.0` собран из ветки `arena/01a1007e-smarty-chumakov`. После
  слияния в `main` следующий релиз выпускается так: `git tag v1.0.1 && git push origin v1.0.1`
  (workflow сам пересоберёт и переопубликует; либо кнопка **Actions → build-and-release-exe → Run workflow**).
* Калибратор и конфиг упакованы внутрь `.exe` (`config/config.json`,
  `config/calibration.json`) и читаются из бандла — приложение офлайн,
  Python на машине не нужен.
* Пересборка вручную у вас на Windows: `powershell -ExecutionPolicy Bypass -File scripts\make_exe.ps1`
  (из папки `spanverify-module`) — результат в `release\spanverify.exe`.
