# Отчёт по корпусам v1 (A1, A2, B)

Все числа ниже получены скриптами репозитория; команда и источник указаны рядом с
каждой группой чисел. Числа режима `demo` отражают **лексический** конвейер
(без весов языковой модели) и научным результатом не являются.

Сводка: `reports/METRICS.json` → блоки `corpus_a`, `corpus_b`.

## 1. Корпус A1 (управляемые подмены)

Команда: `python scripts/build_corpus_a.py --docs data/corpus_a/docs --out data/corpus_a --target 1200 --seed 42`
Источник чисел: `data/corpus_a/manifest.json`, затем оценка
`Verifier(mode="demo").evaluate(...)` через `scripts/collect_metrics.py`.

| Показатель | Значение |
|---|---|
| Пар | 1200 |
| Документов | 60 (синтетические, помечены `synthetic: true`) |
| Чистых пар | 566 (47.2 %) |
| Сплиты | train 840 / dev 180 / test 180 |
| Общих документов между частями | 0 |
| Меток проверено (срез == спан) | 1140+ (все, `manifest.spans_problems = []`) |
| SHA256 `pairs.jsonl` | в манифесте |

Баланс по режимам: `contradiction` 148, `partial` 129, `number_attribution` 93,
`unconfirmed` 83, `excess` 65, `oversight` 59, `missing` 57, `faithful` 566.

### Метрики конвейера на отложенной части (180 пар)

| Метрика | Значение |
|---|---|
| token F1 (precision / recall) | 0.734 (1.000 / 0.580) |
| token FPR | 0.000 |
| token AUC | 0.954 |
| строгий span-F1 (IoU ≥ 0.5) | 0.098 |
| полнота накрытия разметки фрагментами | 0.737 |
| вердикт ответа: F1 (precision / recall) | 0.798 (0.869 / 0.737) |
| вердикт ответа: FPR | 0.136 |

Строгий span-F1 низкий не из-за промахов, а из-за формата: конвейер расширяет
найденный токен до границ предложения, а разметка корпуса узкая (значение или
деталь). Поэтому рядом стоят две другие метрики — полнота накрытия (0.737) и F1 при
расширении разметки до предложения; в токенных метриках это видно как precision 1.000.

### По режимам (отложенная часть, 180 пар)

| Режим | Пар | Вердикт: recall | Вердикт: FPR | token F1 | Накрытие |
|---|---|---|---|---|---|
| `contradiction` | 26 | 0.92 | 0.00 | 0.63 | 0.92 |
| `excess` | 14 | 1.00 | 0.00 | 0.98 | 1.00 |
| `unconfirmed` | 10 | 1.00 | 0.00 | 0.93 | 1.00 |
| `oversight` | 11 | 1.00 | 0.00 | 0.80 | 1.00 |
| `number_attribution` | 13 | 0.77 | 0.00 | 0.00 | 0.77 |
| `partial` | 15 | 0.27 | 0.00 | 0.00 | 0.27 |
| `missing` | 10 | 0.00 | 0.00 | 0.00 | 0.00 |
| `faithful` (чистые) | 81 | 0.00 | 0.14 | 0.00 | 0.00 |

Читать эту таблицу надо честно:

* **`missing` не ловится вообще.** Пропуск детали лексически не виден: в ответе нет
  ни одного подозрительного слова. Для таких случаев нужен режим `hf` или проверка
  по вопросам-контролям; сейчас это открытое ограничение, а не «редкий случай».
* **`partial` ловится на 27 %.** Это следствие того же: отброшенное условие само по
  себе не оставляет в ответе маркера.
* **`number_attribution` — 77 %** и token F1 = 0. Ноль по токенам объясним: правило
  привязки числа помечает фрагмент (`doubtful`), но не меняет маску токенов, поэтому
  в токенных метриках его не видно. Именно для этого добавлен блок `verdicts`
  (уровень ответа).
* **Ложные замечания на чистых парах — 14 %** (11 из 81). На демо-корпусе их не было
  вовсе (0 из 116). Разница объяснима: демо-корпус писался вручную под те же
  формулировки, а корпус A генерирован и его чистые ответы содержат перефразировки,
  на которых лексическое правило иногда срабатывает. Это измеренный факт.

## 2. Корпус A2 (естественные ответы)

Состояние: **не сгенерирован**. Причина — нет GPU и весов; в песочнице доступен
только сухой прогон:

```
$ python scripts/build_corpus_a2.py --docs data/corpus_a/docs --out data/corpus_a2 --dry-run
Задания: 200 (черновик без генерации)
Генерация не выполнялась: нужен запуск на машине с torch/transformers (docs/GPU_ИНСТРУКЦИЯ.md)
```

Числа «hf»-режима на A2 **не измерены** и в отчёте не приводятся. Все метрики A2
появятся после выполнения `docs/GPU_ИНСТРУКЦИЯ.md` и ручной проверки спанов.

## 3. Корпус B (RusHallu-RAG, внешний тест)

Команды:

```bash
python scripts/fetch_rushallu.py --out data/external/rushallu --verify
python scripts/rus_hallu_eval.py --data data/external/rushallu --mode demo --json reports/rus_hallu_eval.json
```

Загрузка: 655 + 345 = 1000 пар, SHA256 обоих CSV совпали с закреплёнными,
423 спана найдены в ответах дословно, 1 неоднозначное смещение.

### Наши метрики (режим demo)

| Метрика | Значение |
|---|---|
| token F1 (precision / recall) | 0.127 (0.362 / 0.077) |
| token FPR | 0.064 |
| token AUC | 0.529 |
| строгий span-F1 | 0.265 |
| полнота накрытия разметки | 0.534 |
| средняя ширина фрагмента относительно разметки | ×4.35 |

### Их метрики (перевод `metrics/span_metrics.py`, сверен с `rouge_score`)

| Метрика | Значение |
|---|---|
| accuracy | 0.424 |
| Jaccard | 0.435 |
| hamming loss | 0.256 |
| ROUGE-1 | 0.541 |
| ROUGE-2 | 0.533 |
| ROUGE-L | 0.533 |

Сравнение с числами статьи: **не выполнено** — значения таблиц не извлечены из PDF,
а придумывать их нельзя (поле `baseline_comparison` = `null`).

Главный честный вывод: на внешнем корпусе demo-режим практически бесполезен
(token F1 0.127 против 0.95 на своём демо-корпусе). Причина не в порогe, а в природе
признаков: лексические суррогаты работают, когда ответ почти дословно повторяет
документ, а внешние ответы — свободные пересказы. Это и есть измеренное обоснование
GPU-этапа; заявлять качество на реальных данных по demo-режиму нельзя.
