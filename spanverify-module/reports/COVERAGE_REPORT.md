# Проверка покрытия фактов (задача 5): что изменено и что измерено

Дата измерений: 2026-10-10. Источник чисел: `reports/coverage_facts.json` (этот же
файл перечитывает `scripts/collect_metrics.py`), команды прогона приведены
ниже. Все прогоны — `mode=demo` (лексические суррогатные признаки, без весов
языковой модели), потому что покрытие — отдельный канал решения, не
зависящий от признаков: оно работает только с текстами ответа и контекста.

## Что изменено в извлечении фактов

1. **Несколько значений в одном предложении.** `extract_facts` возвращает до
   `max_values_per_sentence=4` фактов на предложение. раньше «договор
   заключается на срок 1 год … для 2 года …» давало один факт (первое
   значение, «1 год»), а остальные утверждения оставались незакрытыми; теперь
   извлекаются все, и предикат больше не ищется «до предыдущего значения» —
   для каждого факта левая граница ищется к его собственному значению, иначе
   предмет второго факта съел бы первое значение.
2. **Хвост `text_after_verb` обрезается по союзам** (`_VALUE_TAIL_STOP`):
   значение «составляет десять мегабайт если» — это значение плюс начало
   оговорки. Такое значение не находилось в корректном ответе, и ответ
   помечался пропустившим факт.
3. **Числа-маркеры больше не значения.** `_is_number_marker` отбрасывает
   маркеры перечисления («1) фамилия», «2. дата»), отсылки к номеру нормы
   («п. 7», «ст. 12») и части составного номера («1.16.4.2.»). Это главный
   источник ложных срабатываний на корпусе A3: OCR принёс нумерацию
   подпунктов в каждый фрагмент правки, и «подменённое» число в «1.16.4.2.»
   означало галлюцинацию в дословно верном ответе. Эффект измерен:
   `coverage_fpr_clean` на тестовой части A3 0,1125 → 0,050 (в 2,25 раза).
4. **Исправлен дефект ветки `distorted`.** Условие записывалось как
   `subject_here >= 0`, где `subject_here` — булев результат
   `_subject_in(...)`: сравнение `bool >= 0` истинно всегда, то есть проверка
   «предмет факта назван в этом предложении ответа» не работала, и подменой
   считалось любое несовпадение чисел в любом месте ответа. Теперь
   `subject_here and reproduced`.
5. **Проверка «ответ пересказал это предложение»** (`reproduced`,
   `omit_answer_share=0,9`): перед тем как объявить пропуск или подмену,
   правило убеждается, что предложение ответа вообще относится к предложению
   документа. Сравниваются «каркасы» (`_frame_stems`) — слова предложения без
   чисел и единиц меры. Без этого шага любое предложение ответа с другим
   числом становилось «подменой» (было 0,148 FPR на чистых A3 — стало 0,052).
6. **Ветка «слот не заполнен» (`_omission_span`) — ответ на
   `recall_missing = 0`.** Прежняя логика искала пропуск по «похожести»
   предложений ответа и документа; коллектор корпуса A (`build_corpus_a.py`,
   режим `missing`) отвечает на предложение-якорь фразой «… установлен» —
   похожих слов в ответе почти нет, совпадение всегда падало ниже порога, и
   полнота была ноль при пяти ложных срабатываниях. Новое правило работает на
   уровне придаточных (`_CLAUSE_SPLIT`) и требует трёх признаков: в придаточном
   ответа стоит глагол слота («установлен», «определён», «предусмотрен»,
   «указан», «закреплён», «применяется», …); в нём нет ни одного значения;
   subject факта назван в том же придаточном, и его каркас совпадает с
   каркасом предложения документа не менее чем наполовину. Придаточное условия
   («если иное не установлено договором») не считается слотом — иначе
   шаблонная оговорка каждого корректного ответа давала ложный пропуск.
   Результат: `recall_missing` на A1 0,000 → 0,600 при `precision_missing`
   1,000 и `fpr_clean` 0,000.

## Метрики в `evaluate()`

`Verifier.evaluate()` возвращает блок `coverage` с полями
`enabled`, `pairs_with_context`, `missing_pairs`, `partial_pairs`,
`clean_pairs`, `predicted_missing`, `predicted_partial`, `recall_missing`,
`precision_missing`, `recall_partial`, `precision_partial`, `fpr_clean`.
Те же пять именованных метрик ТЗ доступны с префиксом — их печатает
`python -m spanverify evaluate` и собирает `scripts/collect_metrics.py`:
`coverage_recall_missing`, `coverage_precision_missing`,
`coverage_recall_partial`, `coverage_precision_partial`,
`coverage_fpr_clean`.

Значения `None` означают «не измеримо на этом корпусе» (нет пар нужного типа
или нет ни одного предсказания), а не ноль: `precision_missing = None` —
предсказаний не было вовсе, `recall_partial = None` — в корпусе нет пар типа
`partial`. Нули в таблице — реальные нули.

## Покрытие включено по умолчанию

`Verifier(..., coverage=True)`, `python -m spanverify verify|evaluate` — тоже
включено; `--no-coverage` возвращает историческое поведение. Обоснование
измеренными числами, а не ожиданиями:

* качество ответа improving: F1 по токенам на A1 test 0,734 → 0,781, F1
  вердиктов 0,714 → 0,762 (те же 180 пар, seed 42);
* доля ложных пометок на чистых ответах не выросла: 0,000 на A1 test и на
  всём A1, 0,000 на demo, 0,050 на тестовой части A3 — правило вердикта при
  включённом покрытии строже, чем `risk > 0.5`, и ложных «спорных» ответов
  на A1 стало не больше;
* цена: +20…25 мс на пару при контекстах до 1024 знаков (замер
  `tests/test_metrics_files.py` и прогоны репортёров), т. е. доли процента от
  бюджета p95 в режиме demo.

Решение принято по измеренным числам, а не по умолчанию «как удобно»:
значение `coverage` в `Verifier` и `server.Service` сохраняется, публичный
контракт `verify()` дополнен полем `coverage` (аддитивно), форматы
`weights.json`, `head.json`, `participation.json`, `config.json` не менялись.

## Что осталось недоступно правилу (ограничения, а не недоработки)

* **A3, `missing` (0,000 на тесте, 0,028 на всём корпусе).** Коллектор A3
  (`scripts/build_corpus_a3.py --real`) для типа `missing` обрезает выписку,
  а не вставляет фразу «… установлено»: в ответе нет ни слота, ни значения —
  сравнивать нечего. Чтобы поймать такой пропуск, нужно знать, *какой*
  факт спрашивает пользователь, а question'а у пар A3 нет (в отличие от
  корпуса A2). Это ограничение формулировки корпуса, и оно зафиксировано
  здесь, а не сглажено порогом.
* **A1, `partial` (0,000).** Ответ типа `partial` в A1 пересказывает правило
  без оговорки («договор заключается на срок 1 год для…»), но при этом
  сохраняет числовое значение — правило слота требует «значения нет вовсе», а
  правило несовпадения значений требует различного значения. Для этого типа
  нужна проверка покрытия *условий* (кто вправе, при каком сроке), то есть
  второй класс фактов. Он не сделан: объём работы — отдельная задача, и
  придумывать под него порог было бы подгонкой.
* **Числовые расхождения, порождённые обрезкой A3.** Оставшиеся 4 из 80
  ложных пометок на чистых парах A3 — ответы, у которых обрезка
  разошлась с текстом документа внутри числа («не более 200 000 (двухсот
  тысяч) рублей» против «не более 51 (двухсот тысяч) рублей 00 ко»).
  Формально это действительно несовпадение значения, и правило его ловит;
  разметка корпуса называет пару чистой, потому что дефект в неё не вносили.

## Команды прогона (числа воспроизводятся ими)

```bash
cd spanverify-module
python -m pytest tests/test_coverage.py -q                     # 14 тестов
python - <<'PY'                                                # → reports/coverage_facts.json
import pathlib, sys, json
sys.path.insert(0, ".")
from spanverify.engine import Verifier
from spanverify.dataset import read_pairs
for name, path in [("a1_test_180", "data/corpus_a/splits/test.jsonl"),
                   ("a3_test_177", "data/corpus_a3/splits/test.jsonl"),
                   ("demo_240", "data/demo_pairs.jsonl")]:
    m = Verifier(mode="demo", weights_path=None).evaluate(list(read_pairs(pathlib.Path(path))))
    print(name, json.dumps(m["coverage"], ensure_ascii=False))
PY
python -m spanverify evaluate --dataset data/demo_pairs.jsonl --mode demo | grep -i coverage
python -m spanverify evaluate --dataset data/corpus_a/splits/test.jsonl --mode demo | grep -i coverage
```

`coverage_fpr_clean` на чистых ответах считается только по парам без
размеченных фрагментов (`clean_pairs`), `recall_missing` — по парам, где
размечен пропуск (тип `missing` в разметке или отсутствие в ответе фразы
документа), `recall_partial` — по парам типа `partial`. Числа совпадают с
`reports/METRICS.json` после `python scripts/collect_metrics.py`.
