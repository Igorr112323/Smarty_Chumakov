# SpanVerify — проверка ответа по документу

Модуль принимает документ-источник (**контекст**) и **ответ** (языковой модели
или человека) и отвечает на три вопроса:

1. **Где** в ответе фрагменты, которые документ не подтверждает (точные смещения
   в символах, риск и метка каждого фрагмента);
2. **Насколько достоверен** ответ в целом и какой порог применён;
3. **Какая доля** ответа выглядит машинно-порождённой (независимая оценка).

Работает локально, без передачи текста во внешние сервисы. Ядро, CLI, HTTP API и
веб-интерфейс написаны на стандартной библиотеке Python 3.10+ и запускаются без
установки зависимостей (режим `hf` требует `torch` и `transformers`).

```
python -m spanverify server                       # сервис + интерфейс: http://localhost:8765
python -m spanverify verify --answer "..." --context "..."
```

---

## 1. Честно о статусе

| Что | Состояние |
|---|---|
| Конвейер (признаки → риск → фрагменты → калибровка → вердикт) | реализован, 233 тестов, покрытие 86 % |
| Режим `demo` (без зависимостей) | работает; признаки — лексические суррогаты, годится для проверки конвейера, интерфейса и обучения на своих данных |
| Режим `hf` (реальная модель: внимание + скрытые состояния) | реализован; путь проверен на локально собранной модели, пилот на `rugpt3small` выполняется в CI |
| Числа качества | получены на **синтетическом** корпусе: переносить их на реальные документы нельзя |
| Сборка `.exe` | только в GitHub Actions (PyInstaller не кросс-компилирует); смоук-тест запускает собранный файл на раннере до публикации релиза |

Ключевое ограничение: **метрики демонстрационного корпуса не подтверждают
качество на реальных текстах**. Синтетический корпус порождён генератором по
шаблонам, поэтому цифры на нём оптимистичны по построению. Для отчётности нужен
размеченный корпус реальных пар и прогон обучения/оценки в режиме `hf`.

## 2. Быстрый старт

```bash
cd spanverify-module

python -m spanverify selftest                     # само-проверка конвейера
python -m spanverify server --port 8765           # сервис и веб-интерфейс
python -m spanverify verify --answer "Срок хранения составляет 3 года." \
                            --context "Регламент: срок хранения составляет 10 лет."
python -m spanverify evaluate --dataset data/demo_pairs.jsonl
python -m spanverify train --dataset data/demo_pairs.jsonl --out config/weights.json
python -m spanverify calibrate --dataset data/demo_pairs.jsonl
python -m spanverify analyze --text "Важно отметить, что..."   # исторический детектор «текст написан ИИ»
python -m pytest -q
```

Коды возврата `verify`: `0` — ответ подтверждён документом, `1` — найдены
спорные фрагменты, `2` — ошибка вызова (нет аргументов, недоступна модель).

Готовое приложение для Windows (одна ссылка, установка не нужна):

```
https://github.com/Igorr112323/Smarty_Chumakov/releases/latest/download/spanverify.exe
```

## 3. HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | встроенный веб-интерфейс |
| GET | `/health` | состояние сервиса: режим, калибровка, порог, источник весов |
| GET | `/v1/config` | действующие параметры (веса, порог, изотоника, голова) |
| GET | `/v1/model` | описание признаков, головы, кросс-валидации и режима |
| POST | `/v1/verify` | проверка ответа по документу |

Запрос `POST /v1/verify`:

```json
{"answer": "Срок хранения составляет 3 года.",
 "context": "Регламент 343: срок хранения первичных документов составляет 10 лет.",
 "prompt": null, "max_new_tokens": null, "with_tokens": false}
```

Ответ:

```json
{"score": 1.0, "is_hallucination": true, "ai_share": 0.2857, "ai_share_hard": 0.2857,
 "threshold": 1.0,
 "spans": [{"start": 0, "end": 49, "text": "Срок хранения составляет 3 года.",
            "risk": 0.7749, "label": "likely_hallucination"}],
 "latency_ms": 0.85, "mode": "demo",
 "stats": {"token_count": 7, "mean_risk": 0.29, "p90_risk": 0.78,
           "raw_score": 0.55, "span_threshold": 0.3, "warning": "..."}}
```

```bash
curl -s localhost:8765/v1/verify -H 'Content-Type: application/json' \
  -d '{"answer":"Срок хранения составляет 3 года.","context":"Регламент: срок хранения составляет 10 лет."}' \
  | python -m json.tool
```

## 4. Как это устроено

```
документ + ответ
  ──► токенизация ответа (смещения в символах)
  ──► три признака по токенам: энтропия внимания, масса внимания на документ,
      плотность представлений (косинус к k ближайшим токенам контекста)
  ──► r = w1·Ĥ + w2·(1 − m̂) + w3·d̂
  ──► сглаживание окном 3 (центр 0.6, чтобы не терять узкие подмены)
  ──► порог маски T = μ + z·σ, ограниченный [floor; cap]
  ──► склейка соседних токенов и расширение до границ предложений
  ──► метки: risk ≥ 0.75 → likely_hallucination, иначе doubtful
  ──► оценка ответа s = 0.5·mean(r) + 0.5·mean(верхние 20 %)
  ──► изотоническая калибровка (PAVA) → порог по целевому FPR
```

* **Знак признака массы внимания — отрицательный**: чем больше внимания ответ
  уделяет документу, тем ниже риск. Пилот сравнивает эту гипотезу с «сырой»
  энтропией внимания по слоям.
* **Несодержательные токены** (пунктуация, короткие служебные слова) исключаются
  из оценки риска и из метрик: их нельзя выдумать, и они не должны размывать
  соседние пики.
* **Веса и порог не подбираются по тестовой части**: сетка весов — по AUC на
  обучающей части, маска и порог решения — тоже на обучающей; изотоническая
  калибровка — PAVA; головы (логистическая регрессия) обучаются с 5-кратной
  кросс-валидацией и применяются только если выигрывают у правила на обучении.
* **`demo`-режим** считает признаки лексическими суррогатами (совпадение основ
  слов с документом, шаблонные обороты, плотность n-грамм). Общие для жанра
  обороты («составляет», «установлен в размере») в нём считаются опорой: у
  лексического суррогата нет способа увидеть парафраз. Это задокументированное
  ограничение демо-режима, а не качество.

## 5. Результаты на демонстрационном корпусе

240 пар «документ — ответ» (три типа ответа: подтверждённый, подмена значения,
выдуманное утверждение), **групповое разделение 70/30 по субъектам** (без
пересечения тем между обучением и проверкой), обучение seed 42:

| Метрика | Отложенная часть, 72 пары | Весь корпус, 240 пар |
|---|---|---|
| token precision / recall / F1 | 0.991 / 0.918 / **0.953** | 0.976 / 0.928 / **0.951** |
| FPR по токенам | 0.002 | 0.005 |
| AUC по токенам | 0.996 | 0.997 |
| ответы: precision / recall / F1 / FPR | 1.000 / 1.000 / 1.000 / 0.000 | 1.000 / 0.992 / 0.996 / 0.000 |
| фрагменты: полнота накрытия разметки | 1.000 | 1.000 |
| фрагменты: F1 при расширении разметки тем же правилом | 1.000 | 1.000 |
| фрагменты: строгий F1 по узкой разметке | 0.283 | 0.315 |

Критерий приёмки (token F1 ≥ 0.90 при FPR ≤ 0.10) выполнен **внутри этого
корпуса**. Кросс-корпусный тест (обучение здесь, оценка на корпусе другого
генератора, 240 пар) даёт token F1 0.731 при FPR 0.144 — критерий не выполняется;
это ограничение метода, а не ошибка измерения. Единый файл чисел:
`reports/METRICS.json` (сверяется с документами в CI, `scripts/check_numbers.py`).

Строгий F1 фрагментов с *узкой* разметкой равен 0.283 — это следствие расширения
до границ предложений (ширина ×24 относительно размеченного числа), поэтому рядом
публикуются полнота накрытия и F1 при расширенной разметке. Полный отчёт:
`reports/experiments/experiment.md` (`scripts/run_experiments.py`).

Дополнительно: оценка **доли участия ИИ** (`ai_participation`) — логистическая
регрессия по пяти признакам, средняя вероятность по содержательным токенам,
калибровка на синтетическом корпусе (AUC 1.000 вне выборки — это свойство
синтетики, а не измерение реальных текстов). Отдаётся в `/v1/model` вместе с
полем `participation.calibrated_on`.

**Оговорка.** Это синтетика. Реальные тексты сложнее: парафразы, цитаты, таблицы,
смешанные абзацы. Пока нет прогона на размеченном реальном корпусе, эти числа
нельзя использовать как подтверждение качества.

## 6. Обучение на своих данных

1. Разметить пары в JSONL (по паре на строку):

```json
{"id": "pair-001", "context": "Регламент 343: срок хранения первичных документов составляет 10 лет.",
 "answer": "Срок хранения первичных документов составляет 3 года.",
 "labels": [[50, 51, 1]], "source": "мои документы"}
```

`labels` — отрезки `[начало, конец, метка]` по **символам ответа**, где `1` —
фрагмент, не подтверждённый документом.

Шаблон с заполненными полями: `python scripts/make_markup_template.py --out my_pairs.jsonl --count 20`.

2. Обучить параметры и посмотреть метрики:

```bash
python -m spanverify train --dataset my_pairs.jsonl --out config/weights.json --seed 42
python -m spanverify evaluate --dataset my_pairs.jsonl
python scripts/run_experiments.py --dataset my_pairs.jsonl --out reports/my
```

3. Для режима `hf` установить `torch`/`transformers` (`requirements-hf.txt`) и
обучить/оценить той же командой с `--mode hf` (нужны веса модели в кэше).

Пороги не подбираются по тесту: если F1 ниже 0.90, дорабатываются признаки, а не
порог. Что было сделано и почему — в `PROGRESS.md`.

## 7. Сборка и публикация

```bash
python scripts/make_zipapp.py --out release      # release/spanverify.pyz (~1.2 МБ, нужен Python 3.10+)
python -m PyInstaller spanverify.spec --noconfirm --clean   # только на Windows
```

`spanverify.spec` кладёт `config/` и `data/` внутрь `.exe` (однофайловая сборка,
`console=True`, исключены `torch`/`transformers`/`pandas` и прочее тяжёлое).
Приложение ищет параметры по порядку: рядом с `.exe` → внутри бандла
(`sys._MEIPASS`) → значения по умолчанию; источник виден в `/health`
(`weights_source`).

Публикация идёт из CI: `.github/workflows/build-and-release-exe.yml` собирает
onefile `.exe`, onedir-архив и zipapp, **запускает собранный `.exe`** (проверка
`/health`, подмена факта, подтверждённый ответ, автономность без папки `config`),
считает `SHA256SUMS.txt` и только после успешных проверок публикует релиз.

## 9. Ограничения и этика применения

* **Метод ошибается.** Результат — вероятностная оценка и указание на фрагменты
  для перечитки, а не доказательство. Его нельзя использовать как единственное
  основание для дисциплинарных или юридических решений.
* Режим `demo` не измеряет достоверность: он проверяет конвейер. В каждом ответе
  стоит предупреждение `warning` — не переносите эти числа в отчёты.
* Короткие ответы (1–2 предложения) оцениваются с высокой дисперсией.
* Калибровка привязана к жанру и языку корпуса: перенос на другой домен без
  переобучения снижает качество.
* Порог решения выбирается по целевому FPR; если цена ложного обвинения высока,
  целевой FPR нужно снижать (и это видно в отчёте обучения).

## 10. Лицензия и состав поставки

Модуль поставляется как есть: код, тесты, скрипты обучения и сборки,
демонстрационный корпус и отчёты. Для отчётности используются:
`reports/experiments/experiment.md` (метрики), `config/weights.json` (параметры
метода), артефакты CI (`pilot-report`, `spanverify-windows-x64`) и протокол
`python -m spanverify selftest`.
