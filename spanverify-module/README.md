# SpanVerify — локализация фрагментов текста, написанных ИИ

Модуль принимает документ и отвечает на два вопроса:

1. **Где** в тексте находятся фрагменты, похожие на машинную генерацию (с точными
   смещениями в символах и токенах);
2. **Какая доля** документа написана ИИ (в символах и словах).

Работает локально, без передачи текста во внешние сервисы. Ядро, CLI, HTTP API и
веб-интерфейс написаны на стандартной библиотеке Python 3.10+ и запускаются
без установки зависимостей.

```
python -m spanverify serve          # сервис + браузер: http://localhost:8000
python -m spanverify analyze --file документ.txt --json
```

---

## 1. Честно о статусе

| Что | Состояние |
|---|---|
| Конвейер (признаки → калибровка → фрагменты → оценка доли) | реализован и покрыт тестами (81 тест) |
| Демо-режим `surrogate` (без зависимостей) | работает; нужен для проверки конвейера и интерфейса |
| Режим `hf` (реальная модель: энтропия внимания + эмбеддинги) | код готов, требует `torch`/`transformers` и **ваших** размеченных данных для калибровки |
| Числа качества | ниже приведены результаты на **синтетическом** корпусе; переносить их на реальные документы нельзя |
| Сборка `.exe` | spec и PowerShell-скрипт готовы; Windows-бинарник собирается на Windows или в GitHub Actions |

Ключевое ограничение: **метрики демонстрационного корпуса не подтверждают
качество на реальных текстах**. Синтетический корпус порождён одним генератором,
поэтому цифры на нём оптимистичны по построению. Для отчётности по договору нужен
размеченный корпус реальных документов и прогон `scripts/run_experiments.py` в
режиме `--backend hf`.

## 2. Быстрый старт

```bash
cd spanverify-module

# 1. Проверить работоспособность
python -m spanverify selftest

# 2. Запустить сервис и веб-интерфейс
python -m spanverify serve --open-browser        # http://localhost:8000

# 3. Проверить текст из командной строки
python -m spanverify analyze --text "Важно отметить, что данный метод..." --json
python -m spanverify analyze --file отчёт.txt --explain
cat статья.txt | python -m spanverify analyze

# 4. Тесты
pip install -r requirements.txt
python -m pytest -q
```

Демонстрация режима и генерация корпуса:

```bash
python -m spanverify demo --n 240 --seed 1312 --out data/demo_dataset.jsonl
python -m spanverify calibrate --dataset data/demo_dataset.jsonl --out config/calibration.json
python scripts/run_experiments.py --dataset data/demo_dataset.jsonl --out reports/demo
```

## 3. HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | встроенный веб-интерфейс |
| GET | `/health` | состояние сервиса, бэкенд, признак калибровки |
| GET | `/v1/config` | действующая конфигурация |
| GET | `/v1/model` | описание бэкенда и калибровки |
| POST | `/v1/verify` | проверка текста: `{"text": "...", "threshold": 0.47, "explain": false}` |

Пример:

```bash
curl -s localhost:8000/v1/verify -H 'Content-Type: application/json' \
  -d '{"text":"Важно отметить, что данный метод обеспечивает эффективное решение."}' | python -m json.tool
```

Ответ содержит: `verdict`, `ai_fraction` (доля найденных фрагментов),
`ai_fraction_soft` (диагностическая ожидаемая доля), `ai_fraction_tokens`,
`spans[]` (смещения, токены, средняя и пиковая вероятность), `warnings[]` и
`meta` (включая статистику калибровки).

Дополнительно: `streamlit run ui/streamlit_app.py` (опционально,
`pip install -r requirements-ui.txt`) и Docker (`docker build -t spanverify .`).

## 4. Как это устроено

```
текст ──► токенизация (непрерывное покрытие) ──► признаки по токенам
      ──► взвешенная оценка ──► сглаживание ──► изотоническая калибровка
      ──► порог ──► фрагменты ──► расширение до границ предложений ──► отчёт
```

**Признаки (режим `hf`, целевой):**

* *предсказуемость* — `1 − H_norm` энтропии внимания последнего слоя
  (усреднение по головам, нормировка на `log(seq_len)`);
* *контекстная плотность* — средняя косинусная близость контекстного вектора
  скрытого состояния к `k` ближайшим соседям по документу (`k = 5`).

**Признаки (режим `surrogate`, демо):** повторяемость содержательных слов,
шаблонные обороты и их плотность в окне, локальная повторяемость, единообразие
ритма. Служебные слова помечаются как неинформативные и восстанавливаются по
окружению, чтобы не разрывать фрагменты.

**Калибровка:** изотоническая регрессия (PAVA) переводит сырую оценку в
вероятность, порог выбирается как максимум F1 при ограничении `FPR ≤ max_fpr`
(по умолчанию 0.1). Обучение — только на размеченном корпусе; в поставке лежит
калибратор, обученный на демонстрационном корпусе.

**Разметка:** фрагменты расширяются до границ предложений и склеиваются —
пользователю показываются целые фрагменты, а не отдельные слова.

## 5. Результаты (демонстрационный корпус)

`scripts/run_experiments.py`, обучение на 168 документах, оценка на 72 отложенных
(240 документов, 58 655 токенов, доля машинных токенов 44.5 %):

| Уровень | Precision | Recall | F1 | FPR | HDR |
|---|---|---|---|---|---|
| Токены | 0.943 | 0.945 | 0.944 | 0.050 | 0.950 |
| Фрагменты (IoU ≥ 0.5) | 0.843 | 0.829 | 0.833 | — | — |
| Символы (по разметке) | 0.796 | 0.992 | 0.881 | — | — |

Средняя абсолютная ошибка оценки доли участия ИИ — 0.141 доли документа
(средний IoU разметки 0.790). Отчёт целиком: `reports/demo/report.md`,
машиночитаемый вариант — `reports/demo/report.json`, график распределения
вероятностей — `reports/demo/probabilities.svg`.

**Оговорка.** Это синтетика. Реальные тексты сложнее: там есть
редактированные машинные фрагменты, цитаты, формулы, смешанные абзацы.
Пока не проведён прогон на размеченном реальном корпусе, эти числа нельзя
использовать как подтверждение качества в отчётности.

## 6. Обучение на своих данных

1. Разметьте корпус в JSONL (по документу на строку):

```json
{"id": "doc-001", "text": "...", "labels": [[0, 431, 1], [431, 800, 0]]}
```

`labels` — отрезки `[начало, конец, метка]`, где 1 — фрагмент, написанный ИИ.

2. Обучите калибратор и подберите порог:

```bash
python -m spanverify --backend hf calibrate --dataset data/real.jsonl --out config/calibration.json
```

3. Снимите полный отчёт (включая сетку порогов):

```bash
python scripts/run_experiments.py --dataset data/real.jsonl --backend hf --out reports/real
```

Минимальный объём для устойчивой калибровки — от 100 документов и ~20–30 тыс.
токенов; разметка «на уровне абзаца» допустима, «на уровне слова» — не
требуется.

## 7. Сборка одного файла

**Вариант «здесь и сейчас» — zipapp** (один файл, нужен Python 3.10+ на машине):

```bash
bash scripts/build_zipapp.sh        # release/spanverify.pyz (~1 МБ)
/tmp/spanverify.pyz selftest
```

Конфигурация и калибратор упаковываются внутрь архива, приложение читает их
оттуда. Проверено: собранный `spanverify.pyz` запускается из любого каталога,
проходит `selftest` и находит калибратор.

**Нативный `.exe` (Windows)** — PyInstaller не кросс-компилирует: сборка
выполняется на Windows или в CI. Требуется, чтобы у сборщика была доступна
разделяемая библиотека Python (`libpython3.x.so` / `python3x.dll`); на
серверных Debian-образах её часто нет — это штатное ограничение окружения,
а не модуля.

**Windows-машина**

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make_exe.ps1
# результат: release\spanverify.exe (+ config\ и data\ рядом)
```

**Linux/macOS**

```bash
bash scripts/build.sh            # release/spanverify
```

**Без Windows-машины** — GitHub Actions: workflow
`.github/workflows/build-and-release-exe.yml` (запуск вручную или по тегу `v*`)
прогоняет тесты на Python 3.10–3.12, собирает onefile `.exe`, onedir-вариант и
zipapp, **сам запускает собранный `.exe`** на раннере (проверяет `/health` и
делает реальный `POST /v1/verify` с русским текстом), считает контрольные
суммы и публикует релиз.

Готовый файл после публикации:

```
https://github.com/Igorr112323/Smarty_Chumakov/releases/latest/download/spanverify.exe
```

Скрипты сами прогоняют тесты, при отсутствии калибратора обучают его на
демо-корпусе и проверяют собранный файл командой `selftest`.

Лицензия и оговорка по сборке: `.exe` не проверялся в этом окружении (нет
Windows и разделяемой библиотеки Python для PyInstaller). Что именно
проверено, а что нет — в разделе «Честно о статусе».

## 9. Ограничения и этика применения

* **Детекторы ИИ ошибаются.** Ни один метод не даёт доказательства авторства.
  Результат — вероятностная оценка, её нельзя использовать как единственное
  основание для дисциплинарных или юридических решений.
* Режим `surrogate` не измеряет достоверность: он проверяет работоспособность
  конвейера. В каждом его ответе ставится предупреждение — не переносите эти
  числа в отчёты.
* Короткие тексты (1–2 предложения) оцениваются с высокой дисперсией: чем
  меньше документ, тем шире доверительный интервал.
* Тексты, прошедшие ручную правку или «пересказ» моделью, распознаются хуже.
* Калибровка привязана к жанру и языку корпуса: перенос калибратора на другой
  домен без переобучения снижает качество.

## 10. Лицензия и состав поставки

Модуль поставляется как есть, вместе с тестами, скриптами сборки, демонстрационным
корпусом и отчётом по нему. Для включения в отчётность используются:
`reports/*/report.md` (результаты), `config/calibration.json` (параметры
калибровки) и протокол прогона `python -m spanverify selftest`.
