# Корпус v1: состав, формат и правила работы

Документ описывает два корпуса, которые появились в версии 1.3.0: **A** (наш,
управляемые подмены и естественные ответы) и **B** (внешний бенчмарк RusHallu-RAG).
Он же служит инструкцией: все команды можно выполнить в чистом клоне репозитория.

Коротко о правилах, которые нельзя нарушать:

* **B — только тест.** На корпусе B нельзя ни обучать, ни калибровать: иначе
  «внешняя проверка» превращается в проверку на обучающей выборке.
* **Сырьё B не коммитится.** Лицензия данных не подтверждена: в репозитории
  бенчмарка есть бейдж Apache-2.0, но файла `LICENSE` нет, у наборов на HuggingFace
  лицензия не указана. Поэтому в репозитории лежат скрипт с закреплённой ревизией и
  SHA256, а сами CSV скачиваются локально (`data/external/` в `.gitignore`).
* **Никаких выдуманных чисел.** Если `hf`-этап не запускался (нет GPU), в отчёте
  стоит «не измерено», а не «примерно так же».
* **Метки B не переразмечаются.** Их спаны берутся как есть; наш конвейер только
  предсказывает и сравнивается с ними.

## 1. Корпус A1: управляемые подмены

Собран скриптом `scripts/build_corpus_a.py`. Документы — синтетические шаблоны
(«Регламент учёта № N»), в каждом 6–8 фактов вида «Для <субъект> <признак>
составляет <значение>». Скрипт строит ответ и **сам ставит метку** на испорченный
фрагмент, поэтому для каждой пары известно, что именно сломано.

| Режим | Что с ответом | Тип в таксономии бенчмарка |
|---|---|---|
| `faithful` | без искажений (чистые пары, ≥ 40 %) | `faithful` |
| `contradiction` | значение заменено на другое | `Contradiction` |
| `partial` | отброшено условие, смысл искажён | `Partial` |
| `number_attribution` | число взято из факта **другого** объекта | `Contradiction` (подтип) |
| `unconfirmed` | добавлено утверждение, которого нет в документе | `Unconfirmed` |
| `missing` | обязательная деталь пропущена | `Missing` |
| `oversight` | важное значение потеряно при пересказе | `Oversight` |
| `excess` | добавлена лишняя деталь | `Excess` |

Команда сборки:

```bash
python scripts/build_corpus_a.py --docs data/corpus_a/docs --out data/corpus_a --target 1200 --seed 42
```

Что получается (фактические числа, `data/corpus_a/manifest.json`):

* 1200 пар, 60 документов;
* чистых 566 (47.2 %), каждый тип ошибки — не меньше 40 пар (минимум у `missing` — 57);
* сплиты 840 / 180 / 180, разбиение **по документам**, `shared_groups = 0`;
* SHA256 файлов и документов в манифесте; повторный запуск с тем же `seed` даёт те
  же пары (проверяется тестом).

### Подтип «атрибуция числа»

Обязательный подтип: ответ берёт числовое значение, которое в документе относится к
**другому субъекту** (например, «срок хранения для первичных документов — десять
лет», хотя десять лет записано для вторичных). В корпусе 93 такие пары. Именно на
них работает правило, закрытое как дефект D в версии 1.2.1.

## 2. Корпус A2: естественные ответы (нужен GPU)

Черновик собирает `scripts/build_corpus_a2.py`: из документов достаются факты,
к каждому строится вопрос и промт («ответь строго по документу»), модель отвечает,
наш конвейер даёт **черновую** разметку.

```bash
# без GPU: только задания и промты
python scripts/build_corpus_a2.py --docs data/corpus_a/docs --out data/corpus_a2 --dry-run

# на машине с GPU
python scripts/build_corpus_a2.py --docs data/corpus_a/docs --out data/corpus_a2 \
    --model ai-forever/rugpt3small_based_on_gpt2 --limit 200
```

Черновая разметка **не считается истиной**: каждая пара помечена
`"needs_expert_review": true`, а вердикт конвейера хранится как `draft_verdict`.
Проверка человеком — через `scripts/review_server.py` (см. раздел 4). Пошаговая
инструкция для машины с GPU — `docs/GPU_ИНСТРУКЦИЯ.md`.

## 3. Корпус B: внешний бенчмарк RusHallu-RAG (только тест)

Источник: `feudor2/RusHallu-RAG`, закреплённый коммит
`345907f983da91e1b7720b5944d982ea9c9aeb83`, файлы разметки
`results/annotation/human/merged/sberquad-rag.csv` и `ruscibench-rag.csv`.

```bash
python scripts/fetch_rushallu.py --out data/external/rushallu --verify
python scripts/rus_hallu_eval.py --data data/external/rushallu --mode demo \
    --json reports/rus_hallu_eval.json
```

Проверено нами (команда и вывод — в `reports/rus_hallu_eval.json`):

* 1000 пар, 667 чистых, 333 с галлюцинациями, 423 спана
  (Partial 125, Unconfirmed 116, Contradiction 68, Missing 56, Oversight 36, Excess 22);
* каждый непустой спан находится в ответе модели дословно (423 из 423);
* неоднозначных смещений — 1 (первое вхождение).

В закрытом окружении `raw.githubusercontent.com` и HuggingFace недоступны, поэтому
загрузчик умеет брать те же файлы через GitHub API: `--transport gh`. Данные
сверяются по SHA256, записанным в скрипте; при несовпадении загрузка останавливается
с объяснением (данные могли обновиться на стороне источника).

### Сравнение с числами статьи

Пока значения таблиц статьи не извлечены, в отчёте стоит
`"baseline_comparison": null` и текст «не извлечены». Это сделано намеренно: числа
из PDF не парсились, а придумывать их нельзя. Когда значения будут перенесены в
`reports/rus_hallu_eval.json` вручную (с указанием таблицы), поле заполнится.

## 4. Ручная проверка

```bash
# очередь: 10 % тестовой части корпуса A
python scripts/review_server.py --make-sample --source data/corpus_a/splits/test.jsonl \
    --queue data/review_queue/corpus_a_10pct.jsonl --share 0.10 --seed 42

# сервер: страница с парой, кнопки «верно / неверно / пропустить»
python scripts/review_server.py --queue data/review_queue/corpus_a_10pct.jsonl \
    --out data/review_queue/decisions.jsonl --port 8770
```

Решения пишутся в JSONL (история сохраняется, последнее решение — действующее).
Сервер не имеет доступа наружу и не требует зависимостей. Итог ручной проверки
идёт в `reports/CORPUS_REPORT.md` отдельной строкой: сколько пар проверено, сколько
меток подтверждено, какие расхождения.
