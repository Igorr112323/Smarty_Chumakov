Программа берёт **документ-источник** и **ответ** (языковой модели или
сотрудника) и показывает, какие места ответа документ не подтверждает: подмену
числа, выдуманное утверждение, расхождение со сроком. Никаких внешних сервисов —
всё считается локально.

## Скачать и запустить (Windows)

```
https://github.com/Igorr112323/Smarty_Chumakov/releases/latest/download/spanverify.exe
```

Двойной щелчок → откроется страница `http://localhost:8765` → вставить документ
и ответ → «Проверить». Пошаговая инструкция (включая предупреждение SmartScreen
и как удалить программу) — в [`docs/РУКОВОДСТВО.md`](docs/РУКОВОДСТВО.md).

В релизе также `spanverify-win.zip` (вариант для антивирусов), `spanverify.pyz`
(для Python 3.10+) и `SHA256SUMS.txt` с контрольными суммами.

## Что можно сделать из командной строки

```bash
cd spanverify-module

python -m spanverify verify --answer "Срок хранения составляет 3 года." \
                            --context "Регламент: срок хранения составляет 10 лет."
python -m spanverify train --dataset data/demo_pairs.jsonl --out config/weights.json
python -m spanverify evaluate --dataset data/demo_pairs.jsonl   # метрики и критерий качества
python -m spanverify selftest                                   # само-проверка конвейера
python -m spanverify server --port 8765                         # API + веб-интерфейс
python -m pytest -q                                             # 252 тестов
```

Коды возврата `verify`: `0` — ответ подтверждён, `1` — найдены спорные
фрагменты, `2` — ошибка вызова.

## HTTP API (контракт)

```bash
curl -X POST http://localhost:8765/v1/verify -H "Content-Type: application/json" -d '{
  "answer": "Срок хранения первичных документов составляет 3 года.",
  "context": "Регламент 343: срок хранения первичных документов составляет 10 лет."
}'
```

Ответ содержит `score`, `is_hallucination`, `ai_share`, `ai_share_hard`,
`threshold`, `spans` (`start`, `end`, `text`, `risk`, `label`), `latency_ms`,
`mode`, `stats`. Справочные маршруты: `GET /health`, `GET /v1/config`,
`GET /v1/model`, `GET /` — веб-интерфейс.

## Честно о результатах

* Демонстрационный корпус **синтетический**: token F1 0.953 при FPR 0.002
  (отложенная часть) подтверждает работоспособность и самосогласованность
  конвейера, а не качество на реальных документах.
* **Перенос между генераторами проверен и даёт падение**: на корпусе другого
  генератора (числа словами, другие шаблоны) тот же метод даёт token F1 0.717 при
  FPR 0.157 — критерий F1 ≥ 0.90 при FPR ≤ 0.10 там **не выполняется**. Числа:
  `spanverify-module/reports/cross_corpus.json`.
* **Качество фрагментов показано с двух сторон**: строгий F1 по узкой разметке
  0.283 (весь корпус — 0.315; конвейер расширяет найденный токен до границы
  предложения, ширина ×24) и полнота накрытия 1.000. Актуальные числа — в
  `spanverify-module/reports/METRICS.json` (единый файл чисел, сверяется в CI).
* Пилот на малой модели `ruGPT3-small` (CPU, 24 контрастные пары на синтетических промтах) показал
  **отрицательный результат**: признаки внимания не отличают подставленное число
  от правильного. Числа из аннотаций CI прогона `37118455503` (job «Пилот», после
  исправления сопоставления подслов): AUC по слоям и признакам 0.405–0.700,
  типичное значение около 0.50 (энтропия 0.495 [0.326; 0.663], масса внимания
  0.549 [0.375; 0.713], плотность 0.512 [0.346; 0.685] на первом слое); контроль
  корпуса выдержан (копирование числа 1.000 против 0.000), устойчивого
  преимущества масса внимания над энтропией не даёт. См.
  [`docs/ОТЧЁТ_о_НИР_шаблон.md`](docs/ОТЧЁТ_о_НИР_шаблон.md), раздел 7.2.
* Порог решения никогда не подбирается по тестовой части; при недостижении
  критерия дорабатываются признаки, а не порог.
* **Число привязывается к своему объекту** (исправление D, релиз 1.2.1): если ответ
  берёт число из другого факта того же документа («первичные — пять лет»,
  «вторичные — десять лет», ответ про первичные говорит «десять»), фрагмент
  помечается `doubtful`. Правило текстовое и работает поверх обученной головы;
  на чистых парах демо-корпуса ложных срабатываний 0 из 116.
* **Чужой формат датасета отвергается** (исправление E): `evaluate` проверяет схему
  до расчёта метрик и возвращает код 2 с указанием строки, причин и примера
  корректной записи, вместо `F1 0.000 / AUC=nan` с кодом 0.

## Честно о режимах

| Режим | Признаки | Когда годится |
| --- | --- | --- |
| `demo` (по умолчанию в `.exe`) | лексические суррогаты, без весов модели | демонстрация работы, интерфейс, обучение на своих данных |
| `hf` | внимание и скрытые состояния реальной модели (`torch` + `transformers`) | рабочие выводы, научные результаты |

Демонстрационный корпус синтетический: метрики на нём (token F1 0.953, FPR 0.002,
AUC 0.996 на отложенной части) доказывают работоспособность и
самосогласованность конвейера, а не качество на реальных документах. Научные
выводы требует режим `hf` и своя разметка — это делает пилот
(`scripts/pilot_rugpt3small.py`) — пилот на малой модели (`ruGPT3-small`) на синтетических промтах в CI.


**Кросс-корпусный тест:** обучение на демо-корпусе, оценка на корпусе другого
генератора (другие клише, числа прописью, перефразировки). Числа: внутри
корпуса token F1 0.953 / FPR 0.002, кросс-корпус token F1 0.717 / FPR 0.157.
Кросс-корпусный тест показывает переносимость метода на другой генератор,
а не на реальные регламенты; для реальных нужны 1200 пар.

## Историческая ветка (не продукт)

В модуле сохранён прежний текстовый детектор «написан ли текст ИИ» без
документа-источника: команда `spanverify analyze`, модули `detector.py`,
`backends/`, `text.py`, `vectors.py`, `training.py`. Продуктовые пути (API,
интерфейс, `.exe`) его не используют; он оставлен для сравнения постановок и
своих тестов.

## Важное замечание о состоянии папки

Исходная заявка и ТЗ на модуль в репозитории отсутствуют, поэтому исправленная
редакция заявки сделана в виде готовых формулировок
([`docs/ЗАЯВКА_поля.md`](docs/ЗАЯВКА_поля.md)): их можно копировать в поля
АС «Фонд-М». Поля про публикации, дипломную работу и письмо поддержки
заполняет исполнитель — эти данные знает только он.
