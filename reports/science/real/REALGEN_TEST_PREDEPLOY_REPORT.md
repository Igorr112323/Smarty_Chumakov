# REALGEN-R1 official test pre-deployment review

**Status: BLOCKED — frozen full-dev inference bundle is missing.** This preparation registers the intended one-shot evaluation and implements fail-closed authorization/measurement code. It does not authorize, dispatch, or perform the official `test_realgen` run. The PR is for curator review and must not be merged while the model-bundle block remains.

## Sealed-data boundary

Preparation code and ordinary CI must not open the 100-answer `REALGEN_ANSWERS_TEST_REALGEN.jsonl`, test labels/spans, or test-specific answer contexts. Their SHA256 values in `REALGEN_TEST_PREDEPLOY.json` are copied from the existing freeze manifest as metadata; their bytes were not read to prepare this protocol. `real_test` 1200 remains permanently locked and unused.

The official evaluator reads sealed inputs only after all checks pass: explicit `--run-now`, exact `FIRE-REALGEN-1` release code, `workflow_dispatch` on `main`, a real Actions run ID, a ready preregistration whose evaluator hash and input hashes match, and a present model bundle whose SHA256 matches. The workflow is manual-only, serialized, refuses any prior official attempt, has a 40-minute timeout, writes no commits, and publishes the single result through the GitHub Step Summary and check-run `output.text` bridge. The result artifact is retained for 90 days. No workflow was dispatched in preparation.

## Frozen protocol

The fixed decision threshold is **0.5** for all three systems. Subtoken risk probabilities are averaged to word-token probabilities; thresholded token intervals separated by at most one character are merged into predicted character spans. Span matches are one-to-one greedy matches with IoU ≥ 0.5. Answer risk is the maximum word-token score. Brier score and 10-bin equal-width ECE are reported for token and answer levels. FPR uses the fixed 0.5 threshold. Confidence intervals use 5,000 answer/document-cluster bootstrap resamples with seed `20261026` and percentile 95% limits.

The result must report **composite**, **rubert-tiny2 FT**, and **R2-only** independently. The R2-only baseline excludes E1 and old5. Metrics are token precision/recall/F1/FPR/AUC, span precision/recall/F1 at IoU 0.5, and answer-level precision/recall/F1/FPR/AUC; Brier and ECE are additionally reported at token and answer levels. No official test metrics are present in this report or predeployment record.

## Blocking model-artifact finding

The successful Phase B experiment persisted OOF predictions and aggregate metrics, but did **not** persist final full-dev inference artifacts for the composite estimator, the R2-only estimator, or the fine-tuned rubert-tiny2 model. OOF predictions are not substitutes for frozen deployable models. The official evaluator therefore refuses to proceed: `REALGEN_TEST_PREDEPLOY.json` is deliberately marked `BLOCKED_MODEL_ARTIFACTS_NOT_FROZEN`, its model-bundle SHA and Actions run ID are null, and the official workflow fails before opening any sealed input.

Before this preparation can become runnable, a separate dev-only freeze step must produce a complete inference bundle for all three named systems, pin upstream model revisions, record the real Actions run/artifact provenance and bundle SHA256, and update the predeployment record. That step must use dev data only, make no access to the sealed answers/labels/context rows, and receive curator review. No model was refit or calibrated in this preparation.

## Limitations to carry into interpretation

- The synthetic labels are generated by deterministic number/citation rules, so overlapping lexical predictors can show circularity-driven performance.
- A single synthetic generator and 100 held-out answers cannot establish transfer to free-form generation or external generators.
- The previously recorded Phase B OOF metrics are development evidence only and must not be described as official test results.
- The permanent `real_test` 1200 split remains out of scope, unread, and unused.
