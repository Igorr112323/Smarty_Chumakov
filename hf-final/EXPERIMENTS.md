# Эксперименты режима hf: протокол, базовая линия, шаги 2 и 3

Файл — журнал измерений по протоколу [`METRIC_SPEC.md`](METRIC_SPEC.md). Правила
журнала: каждое изменение, влияющее на число, — отдельная запись; записаны и
принятые, и отклонённые варианты; числа сюда попадают **только** из
`reports/hf_protocol/sweep.json` и `reports/hf_final/manifest.json`, ни одно
значение не вписывается вручную. Где артефакта ещё нет, стоит «не измерено» —
это не пропуск, а отсутствие результата на момент коммита.

Грань между этим файлом и README: здесь — причина и ход эксперимента, там —
итоговая таблица. Числа в README сверяются с манифестом скриптом
`scripts/check_numbers.py`; несоответствие валит CI.

## Шаг 2 — не более 10 конфигураций, только на val

Команда прогона (CI, job `sweep`):

```bash
python scripts/precompute_features.py --grid --model ai-forever/rugpt3small_based_on_gpt2 \
  --dataset data/corpus_a3/splits/train.jsonl \
  --split-files "train=data/corpus_a3/splits/train.jsonl,dev=data/corpus_a3/splits/dev.jsonl" \
```

## Шаг 3 — финальная оценка на test (ровно один раз)
Команда прогона — workflow, а не локальный запуск: torch и веса в песочнице
недоступны. Dispatch требует права `actions:write`, поэтому шаг 3 запускается
коммитом, который (1) добавляет `config/hf_final_config.json` с полем
`"step": "final-config"` и зафиксированным порогом, (2) дописывает в
`docs/EXPERIMENTS.md` строку «Порог, зафиксированный до шага 3: <число>» (её сверяет
`tests/test_no_test_leakage.py`), (3) меняет `.github/hf-protocol.trigger` и
(4) содержит метку `[hf-final]` в сообщении. Run'ы без метки считают только
шаги 0–2 — так «один запуск на test» обеспечивается механизмом, а не обещанием.
Grid и sweep при этом пересчитываются заново в том же прогоне: выборка val,
выбор конфигурации и источник порога оказываются в одной цепочке происхождения,
и сверять финал есть с чем.

Сама фиксация — не ручная правка, а команда

```
python scripts/freeze_final_config.py --sweep reports/hf_protocol/sweep.json \
    --primary a3 --run-id <номер прогона CI>
```

Она берёт запись выбранного на val эксперимента из `sweep.json` и пишет
`config/hf_final_config.json` (признаки, классификатор, гиперпараметры, окно,
зазор слияния, порог, seed'ы, отступления, sha256 источника) плюс запись в этот
журнал. Числа в журнал попадают из артефакта, а не из головы: переписать их
рукой — значит сделать финал неперепроверяемым. Повторная фиксация отвергается
(`--force` — только для черновика), как и фиксация при отборе по test или при
ошибке в выбранной конфигурации. Если ни одна конфигурация не прошла
ограничение FPR(val), скрипт применяет стоп-правило (максимальная F1(val)) и
записывает это в `deviations` — отступление попадает и в манифест финала.
Порог из конфигурации применяется ко всем пяти seed'ам без переселекции: шаг 3
не вправе подбирать его заново, иначе фиксировать до запуска было бы нечего.



Перед запуском: выбрать конфигурацию по правилу, зафиксировать её в
`config/hf_final_config.json` (`step: final-config`), добавить запись в этот
файл и поставить тег `freeze-hf-protocol` на коммит с этим состоянием. Дальше —
одна команда, без повторов с другими параметрами:

```bash
python scripts/hf_protocol.py final --config config/hf_final_config.json \
  --grid-cache reports/hf-grid/a3-test --splits data/corpus_a3/splits \
  --seeds 42,43,44,45,46 --include-val --out reports/hf_final
python scripts/hf_protocol.py verify-manifest --manifest reports/hf_final/manifest.json \
  --predictions reports/hf_final/predictions_test.jsonl.gz --check-splits
```

Итог (заполняется из `reports/hf_final/manifest.json`, числа в таблицу
записывает `scripts/render_hf_table.py`, а не человек):

| Метрика | Значение | Уровень | Выборка | Файл-источник | Подтверждающий тест |
| --- | --- | --- | --- | --- | --- |
| F1 / FPR | не измерено | токены | test (a3) | `reports/hf_final/manifest.json` | `tests/test_reported_metrics.py`, `tests/test_criterion_hf.py` |

## Отступления

### Прерванные попытки шага 3 (не второе измерение)

Прогон `38053135407` дошёл до шага «Финальный прогон» и был убит лимитом job'а
(40 минут): на каждый из пяти seed'ов `run_experiment` тратил шесть обучений —
пять фолдов групповой CV ради порога, который к шагу 3 уже заморожен, и одно
итоговое. Манифест не был записан (`write_json` выполняется после всех seed'ов),
предсказания не записаны, `hf-final/` в ветку данных не публиковался,
подтверждающие тесты не запускались. **Чисел уровня test никто не видел**,
поэтому повтор этого замера — не второй прогон на test и не переподбор:
измерение не состоялось. Изменения, снимающие причину: при замороженном пороге
CV не выполняется (`scripts/hf_protocol.py`), лимит `final` поднят до 90 минут,
публикация и загрузка артефактов идут под `if: always()` (чтобы таймаут больше
не мог съесть уже полученный манифест), вторичное измерение A1 вынесено в
отдельный job `final-a1`.

Прогон `38061440215` измерение выполнил и упал на записи артефактов. В логе job'а
остались предсеменные числа: `seed 42…46: F1(test) 0,595041 FPR(test) 0,006565
порог 0,1106` — тест прочитан ровно один раз, тем же замороженным конфигом.
Манифест при этом не появился, и причин было две:

1. `aggregate_seeds` падал на `statistics.pstdev` с
   `AttributeError: 'float' object has no attribute 'numerator'` — на CPython 3.11
   так выглядит NaN среди значений, а NaN там законен: AUC уровня ответов не
   вычисляется, когда в выборке один класс. Падение случалось после цикла по
   seed'ам, до `write_json`, поэтому измерение оставалось без манифеста.
2. `final` не писал `gold_test.jsonl.gz`, а его sha256 читал из несозданного
   файла. Даже без падения это значит «уровни ответов и фрагментов нечем
   пересчитать»: подтверждение шага 3 не состоялось бы.

Оба места — код агрегации и записи **после** вычисления метрик: на сами числа они
не влияют (числа в манифесте пересчитываются из предсказаний `verify-manifest`ом).
Исправления закрыты тестами `tests/test_hf_final_manifest.py`, и  повтор `final`
на синтетическом кеше вызывает `compare_manifest` — тот же пересчёт, что и в CI.
Не-числа теперь пишутся в манифест как `null` с счётчиком `_not_computed`, а не
как «0,0» и не как битый JSON.

Третья попытка — тот же замороженный конфиг (sha256 `1b0e3502df6dea0c…`), тот же
порог 0,1106, те же seed'ы 42–46, никаких изменений признаков и окна: по числам
второй попытки ориентир не достигнут (0,595041 < 0,60), и после этого конфиг не
менялся — переподбор по уже прочитанному тесту обнулил бы измерение. Повтор нужен
только для того, чтобы у измерения был манифест и gold-записи, которые сверяются
тестами.

от протокола (обязательный раздел)

1. **Коммит на конфигурацию.** Требование «каждый эксперимент — отдельный
   коммит» выполнено в форме «каждый эксперимент — отдельная строка
   зафиксированной сетки и отдельная запись журнала»: десять конфигураций
   замирают одним файлом `config/hf_experiments.json` (его sha256 в шапке), а
   считаются одним CI-джобом. Причина: разнести их по десяти коммитам с десятью
   CI-прогонами — то же самое содержание ценой десятикратного ожидания модели,
   а смысл требования (нельзя поменять состав признаков задним числом) закрыт
   хешем файла сетки. Если заказчику нужна буквальная разбивка, она делается
   повторным прогоном того же джоба по одной строке за раз — протокол это не
   запрещает.
2. **`predictions_val.jsonl` сжат** (`gzip`): 1023 пары × ~250 токенов — это
   единицы мегабайт, а артефакт CI обязан читаться; формат строк не изменился,
   тесты распаковывают прозрачно.
3. **Правило уровня ответа в эксперименте** — `оценка ответа = максимум
   токенных оценок`, решение тем же порогом (`_answer_metrics` продукта). Продукт
   принимает решение по вердикту и правилам фрагментов; для шага 1 оно
   используется как есть, для шагов 2–3 подмена неизбежна: у исследуемой модели
   нет вердикта. Первичная метрика (токены) от этого не зависит — на ней критерий
   и измеряется.

4. **Числа шага 2 публикуются одним прогоном.** `sweep` пишет
   `reports/hf_protocol/sweep.json` (все десять конфигураций, обе выборки — val и
   обучающая часть) и `manifest_val.json` — манифест того же формата, что и
   финальный; его проверяет тот же `verify-manifest`. Так расхождение «манифест ≠
   предсказания» ловится до шага 3, а не после.
5. **Timebox на обучение.** Число эпох линейного модельера ограничено сеткой
   (200–800), раундов бустинга — 25–60; ограничение одинаково для всех
   конфигураций и зафиксировано хешем `config/hf_experiments.json`. Оно влияет на
   скорость, а не на выборку: val и test оцениваются полностью, без прореживания.

## Как читать числа

`reports/hf_protocol/sweep.json` — по каждой конфигурации: `threshold`,
`threshold_selection` (folds, число oof-строк, F1/FPR в выбранной точке),
`fit`/`val` (три уровня), sha256 модели. `reports/hf_final/manifest.json` —
то же на test по каждому seed'у плюс mean ± std, железо, версии, время прогона и
хеш всего, что в прогон вошло.

### Шаг 3 — конфигурация зафиксирована (до запуска)

- Конфигурация: `wide-linear` (эксперимент №7 из 10), классификатор `logreg`, признаков 36, окно 0, зазор слияния 2.
- Правило отбора: выбирается конфигурация с максимальным token_f1 на val при token_fpr ≤ 0,40; ties → меньший FPR.
- Порог, зафиксированный до шага 3: 0.110600 — источник: групповая CV по документам на обучающей части, seed 42 (sweep.json, корпус a3).
- Числа на val (a3, тот же порог): токены F1 0.515702 P 0.490566 R 0.543554 FPR 0.021088 AUC 0.92464; ответы F1 0.621469 FPR 0.305882; фрагменты F1 0.233766.
- Seed'ы шага 3: 42, 43, 44, 45, 46 (зафиксированы до запуска, лучший не выбирается).
- Источник: `reports/hf_protocol/sweep.json` (sha256 `c1071f979125301a99b8933f399c3acdbe339bb4a53c54160158326e4adb2956`), прогон CI `38048107448`, код `c7c64bd8d0acbc95d5f2eec0ca044e8ca0f79988`.
