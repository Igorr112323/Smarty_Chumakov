## 2. Часть A. Данные, разметка, метрики

### A1. Корпус синтетический

```
$ python3 -c "...json.loads по data/demo_pairs.jsonl..."
пар: 240 | dataset_version: 2.0-synthetic-pairs
типы: Counter({'faithful': 116, 'value_substitution': 85, 'fabrication': 39})
subject-групп: 15 | мин/макс пар в группе: 10 / 22
дублей ответов в корпусе: 65
```

**Класс: факт.** Корпус построен по шаблонам (`FAQ_TEMPLATES`, `SUBJECTS`), число
предметных групп — 15, то есть проверка идёт на узком наборе тем. Метрики на нём
не доказывают качество на реальных документах — это и заявлено в README/ИТОГ, но
именно они предъявляются как основной результат.

### A2. Утечка между обучением и тестом — есть, влияние измерено

```
$ python3 -c "T._split_pairs(rows, 0.3, 42) → пересечение"
A2 построчный сплит: тест 72 пар | субъектов теста в обучении: 15 из 15
| дословных повторов ответов: 31
пар (вопрос+истинное значение) в обучении и в отложенной части: 29
```

Обучение на групповом сплите (по subject), тест — на отложенных группах
(пересечение субъектов 0):

```
A3 построчный сплит:  токены F1=0.959 FPR=0.002 AUC=0.998
A3 групповой сплит:   токены F1=0.955 FPR=0.003 AUC=0.998
веса в обоих случаях: {'attention_entropy': 0.1, 'ctx_attention_mass': 0.9, 'embedding_density': 0.0}
```

**Класс: факт.** `_split_pairs` (`spanverify/train.py:214`) делает плоский
`random.Random(seed).shuffle` без группировки, поэтому «отложенная часть» в
документах не является независимой. **Важно: эффект утечки мал** (−0.004 F1),
то есть это методологический дефект формулировки, а не подделка метрик.
Исправление всё равно обязательно: групповой сплит + переобучение параметров.

### A3. Метрики фрагментов: в документах показана выгодная сторона


## 3. Часть B. Заявка против фактического состояния

### B1. `ai_share` ≠ «доля участия ИИ» (P0)

```
spanverify/engine.py:403-415
  ai_share (мягкая) — средняя калиброванная вероятность недостоверности
  по содержательным токенам: не зависит от порога ...
  ai_share_hard (жёсткая) — доля содержательных токенов, попавших выше порога маски

Заявка_поля_и_формулировки.md:31-34
  ... и оценки доли участия ИИ в документе ... интегральная оценка доли участия ИИ

$ grep -c "ИИ" docs/ЗАЯВКА_поля.md → 0
$ grep -n "интеллект" docs/ЗАЯВКА_поля.md → (пусто)
```

Три разных текста называют одно поле тремя разными смыслами:
(1) в коде — «средняя вероятность недостоверности» (мера тревожности ответа);
(2) в корневой заявке и паках промтов — «доля участия ИИ»;
(3) в `docs/ЗАЯВКА_поля.md` термина «ИИ» нет вообще (перешли на «достоверность»).

**Класс: факт.** Численно это разные величины: `ai_share=1.0` на ответе из трёх
предложений не означает, что весь документ написан ИИ. Предъявлять `ai_share` как
«долю участия ИИ» **нельзя**. Это P0: эксперт Фонда увидит заявленное и фактическое
разными словами.

### B2. Запрещённые слова в заявочных документах

```
docs/ТЗ_и_календарный_план.md:7 ... в план не включены
```

## 7. Часть F. Научная состоятельность (правда vs самообман)

### F1. Отчёт против реализации

Метрики §7 отчёта воспроизводятся по P/R/F1/FPR и не воспроизводятся по AUC
(см. E2). Формулировка «критерий F1 ≥ 0.90 при FPR ≤ 0.10 выполнен» — верна на
синтетическом корпусе (**факт**), но не подтверждена на реальных документах
(**не проверено**).

### F2. Число параметров против числа примеров

```
config/weights.json: веса 3 (сумма 1 → 2 степени свободы), z/floor/cap 3,
                     изотоника 3 точки, порог 1
config/head.json:    logreg, 6 признаков, обучение на 1164 токенах на фолд
```

**Класс: факт + предположение.** По числу параметров переобучение маловероятно;
главный риск — не размер модели, а синтетический корпус и допущение
`neutral-boilerplate`.

### F3. Приёмный пример «три года» против «пять лет»

```
$ python3 -m spanverify verify --answer "три года" ... --context "...пять лет"
likely_hallucination, score 1.0, порог 1.0, фрагментов 1
```

**Класс: факт.** Работает, но `score` равен порогу **ровно** — совпадение
на границе; при сдвиге данных-калибровки пример может перестать срабатывать.
**Предположение:** лучше зафиксировать пример с запасом (например, «пять лет» →
«три года» на другом контексте) и добавить его в регрессионные тесты.

### F4. Скрытые допущения демо-режима

`PARAPHRASE_WORDS` (служебные обороты считаются поддержанными документом) и
суррогатные признаки внимания действуют только в demo. В README это упомянуто, в
ИТОГ — нет.

**Класс: факт (код+PROGRESS) / не проверено (влияние на реальных текстах).**

## 8. Часть G. Пилот на реальной модели

### G1. Что фактически показал пилот в CI

Аннотации последних прогонов (читаются из `check-runs/<job>/annotations`):

```
контраст: grounded_value_copy_rate = 1.0, unsupported_value_copy_rate = 0.0,
          grounded_overlap_mean = 0.8473, unsupported_overlap_mean = 0.6916,
          contrast_ok = true
парный анализ по токену значения: auc = 0.500, delta = +0.000000 [ci ...], значимо = нет
абсолютные значения признака на токене значения в обеих группах совпали до 6 знаков
(пример: с опорой = 0.544094, без опоры = 0.544094)
```

**Класс: факт.** Контроль данных корректен (число действительно подменено:
copy rate 1.0 против 0.0), но признаковый сигнал не отличается от нуля. После
найденной причины (сдвиг индексов токен→подслова) выводы пилота **устарели** и
требуют перепрогона.

### G2. «Реальная модель» + синтетический корпус

```
scripts/pilot_rugpt3small.py:44
from spanverify.dataset import FAQ_TEMPLATES, SUBJECTS, unit_form
scripts/pilot_rugpt3small.py:117 def build_contrast_pairs(count, seed=2026) ...
```

**Класс: факт.** В текстах пилот описывается как «на реальной модели» — модель
реальная, но контексты контрастных пар строятся из тех же синтетических шаблонов,
что и демо-корпус. Оговорки об этом в ИТОГ нет → P1.

### G3. Значимость

`grep -n "p_value\|p-value" scripts/pilot_rugpt3small.py` → пусто: p-значения не
считаются, решение «значимо/нет» принимается по пересечению бутстрэп-интервалов.

**Класс: факт.** Метод допустим, но требует явной оговорки в отчёте (CI вместо
p-value), иначе эксперт может потребовать привычную статистику.

## 12. Вердикт

**Показывать эксперту Фонда сейчас?**
Как **рабочий прототип с честным самоотчётом** — можно: код собирается, тесты
проходят, релиз опубликован по постоянной ссылке, порог не подбирается по тесту,
есть явные предупреждения о синтетическом корпусе и отрицательном результате
пилота.
Как **метод, подтверждённый на реальных документах** — **нельзя**: нет ни одного
измерения на реальном корпусе, а два текста (заявка и код) называют одно поле
разными смыслами. Пункты P0 № 1 и № 2 должны быть закрыты до предъявления.

**Три главных риска**
1. Эксперт Фонда прочитает `ai_share` как «долю участия ИИ» и получит
   содержательно другое число — репутационный и содержательный разрыв.
2. Доказательная база — синтетика; пилот на реальной модели дал нулевой сигнал и,
   после найденной ошибки сопоставления токенов, ещё не перепроверен. Сейчас
   нельзя утверждать ни «работает», ни «не работает».
3. Поставка: работа `.exe` на ПК без Python и целостность артефакта проверяются
   только человеком; плюс неточные числа в документах подрывают доверие к
   остальным утверждениям.

**Правда и самообман (коротко)**
- Честно: предупреждение о демо-режиме, отрицательный результат пилота,
  отсутствие подгонки порога под тест, смоук exe до публикации релиза, отсутствие
  обещаний «+15 %» и «3–5 раз».
- Было риском самообмана: подача метрик синтетического корпуса как доказательства
  «работоспособности метода»; «отложенная часть» с 15/15 общими subject-группами;
  метрики фрагментов, показанные только в удобном виде; «пилот на реальной модели»
  без оговорки о синтетических парах; числа 0.996/690/207/87 %, не совпадающие с
  воспроизведением.

**СТОП-ФАКТОРЫ — обязан проверить человек (из репозитория недоказуемо)**
1. Запуск `spanverify.exe` на ПК **без Python** (чистая ВМ) — открывается интерфейс,
   `/health` отвечает.
2. Сверка SHA256 скачанного файла с `SHA256SUMS.txt` из релиза.
3. Закрытие окна консоли завершает процесс (проверить в диспетчере задач).
4. Повторный запуск при занятом порту: сервис поднимается на свободном порту.
5. Пример «срок хранения три года» против «пять лет в документе» — вердикт выше
   порога и видимая подсветка фрагмента.
6. Документы для Фонда — глазами: нет запрещённых формулировок, заполнены поля
   «Публикации», «Дипломная работа», «Письмо поддержки».
